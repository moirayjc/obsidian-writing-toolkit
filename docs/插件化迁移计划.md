## 0. 迁移目标

在不改变用户使用方式的前提下，把当前的单一插件代码逐步整理为：

```text
Obsidian Plugin（唯一安装单元）
└─ Host + Services + Feature Modules
```

迁移完成后，用户仍然只安装一个 `writing-toolkit`，插件仍然只有一个 `main.js` 和一个 `styles.css`。变化只发生在内部代码组织和生命周期管理上。

## 2. 总体验收标准

只有满足以下条件，才可以认为插件化架构基本落地：

- 用户仍只安装一个 Obsidian 插件，发布包仍只有一个 `manifest.json` 和 `main.js`。
- `main.ts` 主要承担启动、依赖装配和 Host 接线，不再新增业务功能。
- Feature Module 不直接 import `main.ts`，也不直接 import 兄弟模块的内部实现。
- Feature Module 通过 Host Context 注册命令、视图、事件、编辑器扩展和其他资源。
- 所有注册都有可撤销的 disposer；重新加载后没有重复命令、重复监听器或残留定时器。
- Command + P 永远只有「打开主页 / 打开工具箱 / 打开编辑台 / 打开设置」四个入口；新增功能不得注册新命令。
- `data.json` 仍由 Host 统一写入，模块数据有明确命名空间或迁移方案。
- 禁用某个模块不会删除其数据，也不会让其他模块异常启动。
- 一个模块启动失败时，Host 能记录模块 id 并继续启动其他非依赖模块。
- 现有功能、默认设置、手机端布局和伴随文件行为没有回归。
- `npm run check`、`npm run build`、`npm run verify` 通过，并完成必要的人工回归。

| 移动注册代码改变初始化顺序 | 一次只搬一个注册面，保留兼容包装，对照现有行为 |
| `main.ts` 仍然是状态中心 | 先抽 Services，再搬功能；新功能禁止继续堆进 `main.ts` |
| 多个模块并发写 `data.json` | 只允许 Persistence Service 写入，模块使用数据命名空间 |
| 批注/章纲路径状态脱钩 | 保留现有伴随文件迁移逻辑，模块负责 rename/delete 事件 |
| CodeMirror 扩展重复或状态错乱 | Host 统一组装和刷新；模块不各自修改全局状态 |
| UI 模块互相直接依赖 | UI Shell 只依赖 Services 和插槽 |
| 迁移期间数据损坏 | 保持旧格式、写迁移、备份 `data.json`、保留回滚产物 |
| “插件化”被误解为多插件 | 本文与 `AGENTS.md` 明确写死单插件约束 |
| 运行时动态加载带来安全/审核风险 | 第一阶段只做构建期静态组合，不引入外部 bundle loader |

---

## 12. 明确不做的事

- 不拆成多个 Obsidian 插件。
- 不新增第二个 `manifest.json`。
- 不用 `app.plugins` 做内部模块加载器。
- 不为插件化而重写现有 UI、样式和业务规则。
- 不在迁移中顺手加入新功能。
- 不在没有迁移和备份方案时改变 `data.json` 格式。
- 不把“能热插拔”作为第一阶段验收条件。
