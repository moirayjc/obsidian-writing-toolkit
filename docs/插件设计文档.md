## 1. 这是什么，长什么样

一个 Obsidian 中文网文写作插件（`id: writing-toolkit`，非桌面专属，手机端可用）。约 **63 个 TypeScript 源码文件**，外加 **7,499 行 CSS**；`main.ts` 已从迁移前约 2,965 行降到约 2,429 行。

### 1.1 它长在磁盘上的哪里 ⚠️ 先看这条

```
<你的库>/.obsidian/plugins/writing-toolkit/     ← 仓库根 = Obsidian 实际加载的插件目录
├── src/            55 个 .ts（git 跟踪，约 20,387 行）
├── styles.css      7,499 行（git 跟踪）
├── docs/           本文件所在（git 跟踪）
├── specs/          一页规格与流程（git 跟踪，见 §4.11）
├── tools/          开发工具（git 跟踪，45 个文件）
│   ├── release-check.sh   隐私体检（pre-commit 钩子调它）
│   ├── release.sh         发布：自检 → 构建 → 打包
│   ├── spec/new.js        新建一页 spec（`npm run spec:new`）
│   └── checks/            42 项检查 + 报告落盘（`npm run verify`，含规格形式检查）
├── main.js         ← 构建产物，**git 忽略**，但 Obsidian 加载的就是它
├── manifest.json   版本号（git 跟踪）
├── versions.json   版本 → minAppVersion 映射（git 跟踪）
├── data.json       ← 用户设置与统计数据，**git 忽略**
├── release/        发布打包输出，**git 忽略**
└── _backup/        历史快照，8.3 MB，**git 忽略**
```

> 本文所有相对路径都以这个目录为根（例如 `src/main.ts` = `<你的库>/.obsidian/plugins/writing-toolkit/src/main.ts`）。

**这是一处「原地构建」**：`npm run build` 直接把 `main.js` 与 `styles.css` 写进 `src/` 的上一层——也就是**正在被 Obsidian 加载的那份插件**。所以：

- 改了源码**必须重新构建**才生效（`main.js` 不会自己更新）；
- 构建**没有暂存区**，构建烂了当场就是可用性故障；
- 唯一的安全网是构建前的 `_backup/` 快照（见 §6.3）。

### 2.2 伴随文件（sidecar）——本插件的核心设计

**原则：正文一个字都不动。** 所有「跟着文档走」的数据都写到隐藏目录（批注 / 章纲 / 快照各一个）：

| 数据 | 路径规则 | 格式 | 模块 |
| --- | --- | --- | --- |
| 批注 | `正文/第1章.md` → `.wt-comments/正文/第1章.批注.md`（镜像路径） | 带 Agent 协议的 Markdown（见下） | `comments.ts` / `commentStore.ts` |
| 章纲 | `.wt-outlines/<正文相对路径>`（**连 `.md` 一起镜像**） | 章纲纯文本 | `outlineText.ts` |
| 草稿快照 | `.wt-snapshots/<正文相对路径>/<正文名>-20260826-172407413.md` | 整份 Markdown 副本 | `snapshot.ts` |

> 批注在 2026-10-18 从「正文同目录」迁到 `.wt-comments/`。启动时会把旧的 `正文/第1章.批注.md` 自动 rename 到镜像位置；单个迁移失败时读取会退回旧路径继续工作，数据不丢。正文改名同步搬批注文件，正文目录改名同步搬 `.wt-comments/` 下对应子树。

**作品的目录结构本身不持久化**，每次实时扫描（`project.ts:192-293`）。

路径写法要分清两种：**隐藏目录（`.wt-*`）优先用 `adapter` 直读直写**，**普通路径用 `vault` API**（章纲 `outlineText.ts:254-280` 是前者；批注存储对两种位置都做了兼容）。需要用 YAML frontmatter 时**只用 `vault.process` 行级替换**并留开关，不要整文件重写。

关键工具函数（`comments.ts`）：`sidecarPathFor` / `docPathForSidecar` / `isSidecarPath` / `isCommentSidecarName`。`isInternalPath`（`project.ts:81`）把**任意路径段以 `.` 开头**（`.obsidian`、`.trash`、`.wt-*`）的路径视为内部路径，一律排除出「正文」。

**批注文件的结构与 Agent 协议**（协议抬头逐字引用 `comments.ts:507-517` 的 `SIDECAR_HELP_HEADER`，序列化 `serializeCommentFile:533`，解析 `parseCommentFile:605`）：

```markdown
<!-- 写作工具箱 · 批注文件
这是作者写给「负责修改本文档的 Agent」的批注。

给 Agent 的处理方式：
1. 逐条阅读下方批注，对照每条里的「原文」在源文档中找到对应位置，按「批注」的要求修改源文档；
2. 每条处理完后，只修改该条批注的这些地方——「状态」改为：已处理；在「回复」后写明你做了什么改动（回复多于一行时，从第二行起每行都缩进两格，例如：- 回复：第一点\n  第二点）；
3. 如果你改写了「原文」对应的文字（哪怕只是挪了位置），就把改完后该处现在的文字照抄进「现文」（新增一行：- 现文：……，不要加引号、不要换行）；如果原文一个字都没动，可以不写；
4. 其余文字（包括本说明）请勿改动，也不要删除批注条目。
```

> ⚠️ **抬头原文以 `comments.ts:507-517` 为准**：改协议时改代码里的常量，不要只改这份文档。字段行是可选的——`段落` / `现文` 为空时**不输出该行**（看上面的 `writeField` 条件），所以真实文件不一定有全部 8 个字段。

- 解析**刻意容错**：字段顺序任意、列表符号 `- * +` 都认、未知字段忽略、多行值用**两格缩进续行**（`writeField:523` / `stripIndent`）。**历史上解析器太挑格式会造成「整条批注静默消失」并连带后续保存永久丢失**（见 §5.1 A12），所以宽容是硬要求。

- 批注 id 文件内唯一、**删除后不重排**，新批注取 `max + 1`（`nextCommentId:106`）。
- **库内有真实样例可对照**：`*.批注.md` 已存在于库中（旧版同目录或迁移后的 `.wt-comments/`），改解析器前后都可以拿它做回归验证。**docs/ 里不要贴它的内容**（正文与批注都是个人创作内容）。

### 2.3 「作品」识别：一切统计与权限的地基

`project.ts:19-27` 的注释用**结构识别**把目录树聚合成 `作品 → 卷 → 章`，支持三种组织方式：

- **A. 正文草稿目录**：`P3-某某/P3.3-正文草稿/第1章.md` → 作品 = 草稿目录的上一级，卷 = 草稿目录本身；
- **B. 按卷分目录**：`《书名》/第1卷·某某/第10章 某某.md` → 作品 = `《书名》`，卷 = `第1卷·某某`；
- **C. 章节直接放在目录里**：`《书名》/第1章.md` → 该目录自身即作品。

> 📌 上面这些示例是**脱敏改写过的**。原始注释里写的是**真实作品名与角色名**（见 §7 第 3 条），**改动到 `project.ts` / `main.ts` 这些注释时顺手换掉**，别再把自己或别人的真实作品名写进公开仓库。

识别结果由 `src/services/projectIndexService.ts` 缓存为 `projects()`（作品列表）+
`chapterPaths()`（章节路径集合，判定 O(1)）。库结构变化时 `invalidate()` 失效重建；
`main.ts` 暂时保留 `projectIndex()`、`chapterPaths()`、`isDailyCountFile()` 等同名兼容包装并委托给 Service。

> ⚠️ **「算不算正文」= `chapterPaths().has(path)`**，不是路径关键词匹配。旧实现按「路径里有没有『正文草稿』四个字」判断，结果把 `.wt-outlines` 下镜像的章纲也算进正文、又漏掉按「第N卷」分目录的存档长篇——这条是**已记录的历史坑**（`main.ts:1481-1487`）。**任何新功能想判断「这是不是正文」，都必须用 `isDailyCountFile()` / `chapterPaths()`，不要自己写字符串匹配。**

### 2.4 快照

- 触发：`snapshots.core` 通过自己的 `EventScope` 每 30 秒调用一次
  `DraftSnapshotManager.tick()`，按 `snapshotIntervalMinutes`（间隔）与
  `snapshotIdleMinutes`（空闲）判定；**内容没变就跳过快照**（`snapshot.ts:63`
  注释）。模块还接管编辑器变化、活动文件切换、重命名与卸载结束会话。
- 命名：`原名-YYYYMMDD-HHMMSSmmm.md`（`timestamp:491`），按源文件目录镜像到快照目录下。
- 清理：每文件最多 `snapshotMaxPerFile`（默认 20）份，超出删最旧（`snapshot.ts:415`）。
- 对比/恢复：`snapshotDiff.ts`。弹窗是**左右两栏各自连续滚动**的编辑器（`specs/archive/003-snapshot-diff-free-edit/`）：
  - 左栏 `div` 只读，靠 `user-select: text` 让文字可以像普通文档一样拖选 / 双击 / 跨段选；
  - 右栏 `contenteditable="plaintext-only"`，回车分段、粘贴、跨段删除都按编辑器直觉工作，
    **不产生块级 DOM**，因此整篇文本就是 `textContent`，回写不需要再逐段拼装；
  - 差异只用 **CSS Custom Highlight API**（`::highlight(wt-diff-left-del)` 等四个注册名，
    与 `snapshotDiff.ts` 的 `HIGHLIGHT_NAMES` 一一对应）标色，**不往正文里塞 span**，
    否则复制会带出多余换行；环境不支持时降级为无高亮，功能照常；
  - 「复制选中」走 `snapshot.ts` 导出的 `copyTextToClipboard()`（桌面 Electron / 移动端 Web Clipboard），
    「复制快照」仍保留整份复制；
  - **自动保存**：右栏停止输入约 1 秒（`AUTOSAVE_IDLE_MS`）后自动写回文档；按钮「保存」与
    `Cmd/Ctrl+S` 可立即写回。状态在 meta 行末尾实时显示：`已保存 / 未保存 / 正在保存… / 保存失败`。
    - 写回只能整篇替换编辑器内容，所以撤销粒度 ≈ 空闲阈值；阈值调小会让撤销碎成一两个字。
    - **一次对比会话只备份一份快照**（`backedUp`）：否则每输入一次就存一份，20 份的保留上限
      会被一次会话挤光，真正的历史版本反而没了。
    - 关窗先尝试保存一次，保存成功直接关；只有仍写不进去（文档已关闭 / 被外部改动）才问是否放弃。
  - 弹窗打开时把编辑器内容记成 `baseline`（之后每次成功写回都前移）：写回前比对它，
    **文档被外部改过就拒绝写入**，不覆盖别人的改动；它同时是「未保存」的判据；
  - 恢复 / 应用走「程序化编辑」通道（见 §3.4），并且**会临时关掉海明威模式**（`replaceEditorText`）。

> 为什么不再逐行对齐：逐块对齐（左右各一列 `.wt-diff-line` + 右侧每行一个 `contenteditable`）
> 与「整篇连续编辑」在同一个 DOM 结构里互斥。用户明确要后者，于是差异改用行内高亮表达。

### 2.5 字数统计

`wordcount.ts`，先剥两层再数：

> `FeatureContext.services.wordcount`。

> **设置迁移期入口**：设置契约统一在 `src/settingsSchema.ts`，读取、默认值
> 合并、旧格式恢复和变更通知统一由

## 3. 关键机制（改功能前必读）

### 3.1 主插件类的状态

`main.ts` 的 `WritingToolkitPlugin` 仍承担插件入口、统计历史、界面记忆和 UI Shell 接线，但阶段 4 后不再拥有快照管理器、批注缓存、番茄计时器或日历实例。它们分别属于 `snapshots.core`、`comments`、`pomodoro`、`calendar`；`main.ts` 只持有模块引用和稳定的兼容/操作端口。作品索引缓存属于 `ProjectIndexService`。阶段 5 后，UI Shell 通过 `src/uiShellContext.ts` 获取统计、偏好、导航、最近文档与模块操作端口，不再引用 `WritingToolkitPlugin` 的类型。

**热更新有两条通道**，都不用 Obsidian 的 `Compartment`：

- 已迁移模块通过 `services.settings.subscribe()` 自己比对关心字段；写盘后 `saveSettings()` 调用 `publishChanges()` 广播，模块据此刷新编辑器或 DOM。`editor.typewriter`、`editor.hemingway`、`editor.format-toolbar`、`appearance.typography` 都走这条。
- 快照 UI、章纲、批注、番茄钟、日历和六个编辑辅助模块也都自行订阅设置。`main.ts` 只剩章节识别相关的 `lastDraftKeywords` / `lastChapterExcludeNames`，用于让作品索引立即失效重建。

**新增一个需要热生效的开关，优先在所属模块里订阅并处理；只有迁移期旧代码才继续加 `lastXxxSig`。**

#### 格式工具条

- **触发**：选区浮出（`ViewPlugin.update()` → `scheduleRefresh()`），最终进入 `applyFormatOnView`。命令面板刻意不注册格式命令。
- **定位**：锚在 `state.selection.main.head`，先加 `is-visible` 量尺寸，默认在下方 8px，下方放不下且上方够则翻到上方，四周夹 8px 边距。
- **必须在 `view.requestMeasure({read})` 里读坐标**——CM6 更新期间读布局会抛 `Reading the editor layout isn't allowed during an update`。
- **气泡挂在 `document.body`**，CSS `position: fixed; z-index: var(--layer-popover)`，且**刻意不进 `.wt-*` 主题作用域、直接用 Obsidian 原生变量**，以便在任何主题下跟系统气泡一致。
- **手机端三件套**：点按钮会让编辑器失焦 → 用 `interacting` 标志 + document `pointerup` 捕获监听，失焦期间不收起；`mousedown` 一律 `preventDefault` 防止选区被抢。
- **显示判定的顺序就是代码顺序**（`formatToolbar.ts:292-331`）：`composing` → 非 Markdown 编辑器 → 范围判定（格式与批注**分别**判定，批注可「全库浮出」）→ 选区全空 → 无焦点且非点按气泡中 → `coordsAtPos` 为 `null`。**每条隐藏路径都先记原因再隐藏并计数**（诊断数据 `formatToolbarDiag`），排查时看计数就知道卡在哪一步。
- **只在真 Markdown 编辑器里生效**：用 `state.field(editorInfoField, false)` 判存在（`formatToolbar.ts:246-249`）——搜索框等其它 CM6 实例必须排除。
- **范围三档** `formatToolbarScope`：`all` / `all-except-chapters`（默认）/ `library-only`，判定在 `features/formatToolbarModule.ts` 的 `allowsPath()`；右键批注入口与诊断复用同一判定。
- **包裹与还原**在 `formatWrap.ts`，是**不 import 任何东西的纯函数**（便于单测），返回 `{changes, selFrom, selTo}`。要点：选区要**留在正文文字上**（方便连加多种格式）；单星斜体只认**奇数层**，双字符记号够层数即可；字色用固定 `<span style="color: #hex">`，识别开始标签只回看选区前 96 字符。

#### 批注的渲染（改批注前必读）

**形态**：`StateField<DecorationSet>`，理由写在 `commentDecor.ts:7-10`——**块级装饰不允许来自 ViewPlugin（CM6 会抛 RangeError）**，且状态字段保证装饰在视口计算前已确定。

**两样痕迹**：
1. **原文底色标记** `Decoration.mark`（`class="wt-comment-mark"` + `data-wt-cid` + `title`）。**只有 `via !== "paragraph"` 才画**——定位退到「整段」时原文已大改，画底色会把整段涂掉。
2. **行尾脚注序号** `Decoration.widget(side: 1)`，`span.wt-cnote`，`textContent = 批注 id`；段落定位时落在该段末尾。它的 `eq()` **必须覆盖 `toDOM()` 用到的每个字段**（`id`/`status`/`via`/`content`/`reply`）——漏了就会复用旧 DOM，tooltip 一直显示旧文字（这是修过的 A17）。

**点击跳转的四个条件**（`commentDecor.ts:238-254`）——为的是**避免拖动选择被批注的文字时误跳侧栏**：同一个 cid、位移 `|dx|+|dy| ≤ 4`、间隔 ≤ 600ms、能在缓存里找到该 id。

**`dispatchCommentRefresh` 是唯一的外部数据 → 装饰重建入口**（`commentDecor.ts:52-64`）：
- `view.composing` 时**400ms 后重试**——拼字期间 dispatch 会打断拼音输入；
- try/catch 吞掉「视图已销毁」；
- 数据变化**不会**自动重建装饰，必须显式调它。

**为什么编辑器里一个浮层都没有**：跟随光标的卡片会随正文滚动而「跳」，看着累。所以正文里只有标记 + 脚注号；列表、编辑、删除、标记已处理全在**工具箱侧栏的「批注」标签**；写批注/改批注用**屏幕居中**的输入框（`CommentDraftModal`）。这些交互、编辑器扩展、文件事件和侧栏插槽都由 `comments` 模块统一管理。

> 这条经历过三轮返工才定下来：先做「跟随选区浮层」→ 用户反馈*「会让编辑器内的批注卡片也跟着跳来跳去，看上去并不舒服」*→ 尝试原地更新同一个 DOM → 用户仍是*「还是会跳，不如不要编辑器内的卡片，只保留侧栏的卡片」*→ **最终把 `commentPopover.ts` 整个删掉**。**不要在编辑器里再加任何跟随文字的浮层。**

**跳转链路**：点标记/脚注号 → `onRevealComment` → `revealCommentInPanel`（`main.ts:1899-1918`）→ `openSidebar()` → `sidebar.revealCommentCard`（`sidebar.ts:528`）→ `CommentPanelBody.revealCard`（`commentView.ts:101-126`，先放开「只看待处理」与已处理折叠 → 重渲染 → `scrollIntoView({block:"nearest"})` → `is-revealed` 闪一下）。

**侧栏整段的设计要点（改它会连锁坏掉）**：

- **侧栏 DOM 刚 `setViewState` 时还没建好** → `reveal` 立即失败要在 **120ms 后重试**（`main.ts:1907-1912`）。
- **面板用「内容签名」跳过重绘**，否则会出现「要点两次才跳」；异步渲染带**代数 `renderSeq`** 丢弃晚到的结果；重建后**还原滚动位置**（`commentView.ts:73-80`、`158-171`、`295-299`）。
- **跳转前必须放开筛选/折叠**，否则卡片在「只看待处理」或已处理折叠组里等于不存在（`commentView.ts:101-112`）。
- ⚠️ **已知缺陷**：`revealCommentInPanel` 里 `void path`（`main.ts:1917`）**没有用上这个 path**，面板数据取的是**活动文档**（`getCommentPanelModel` 用 `activeCommentDocPath()`）。所以在**后台编辑器**（不是当前活动文档）里点批注标记，`revealCard` 找不到卡片会**静默返回**。这是 §7 待办之一。


**锚点定位（4 层 / 5 种 `via`）**（`comments.ts`，装饰 / 面板 / 跳转共用同一实现）：

| 顺序 | `LocateVia` | 界面文案 |
| --- | --- | --- |
| 1 | `present` | 按现文定位 |
| 2 | `exact` / `fuzzy` | 精确命中 / 已自动重新定位（忽略空白差异） |
| 3 | `residue` | 原文已改写，按上下文定位（段内残余：取原文前后的文字各 ≤28 字来夹；**头、尾都不到 4 字就放弃**；尾部须在起点后 600 字内） |
| 4 | `paragraph` | 原文已改写，定位到这一段（整段紧凑匹配；否则相似度 ≥0.55；候选段长 ≥6 字；同分按 `paragraphHint` 就近） |
| — | `null` | 锚点失效（原文已大改）→ 面板出现「重新绑定」按钮；**重新绑定必须清掉旧的「现文」**，否则下次定位又被它带偏（`main.ts:1842`） |

前两层（`exact`/`present`）算精确命中，其余标为「已迁移」。

| 工具箱（侧栏） | `writing-toolkit-sidebar` | `.wt-sidebar` | 写作 / 批注 / 快照 / 章纲 等标签页 |
| 编辑台 | `writing-toolkit-workbench` | `.wt-wb` | 按作品管理章节、搜索、复制干净正文、资料库、读者手机预览 |

侧栏用**自建标签页系统**（`wt-settings-tabs` / `wt-settings-tab` / `wt-settings-panels`，`sidebar.ts:333-537`），不是 Obsidian 的 `Setting`；卡片走 `wt-tb-card`，与主页 `.wt-card` 同一套视觉语言。

工具箱「章纲」标签是**阅读态（Markdown 渲染）+ 编辑态（源码 textarea）双态**：有内容时默认先渲染，点顶栏铅笔或双击正文才进入编辑，失焦保存后回到阅读态（空章纲则直接进编辑态）。渲染走公开 `MarkdownRenderer`，样式在 `styles.css` 的 `.wt-outline-preview`。

#### 手机端：两套判定 + 三种手段

**⚠️ 两个判定函数语义不同，用错就出 bug**：

| 函数 | 判据 | 什么时候用 |
| --- | --- | --- |
| `isMobileUI()`（`mobile.ts:7-9`） | `body` 上有没有 `wt-mobile` 类 —— 即「**是否按手机版布局呈现**」，**桌面预览也算** | 布局相关分支（`workbench.ts:1275` 关掉 HTML5 拖拽、`mobileStatusBar.ts:64` 决定要不要显示） |
| `isPhoneDevice()`（`mobile.ts:12-15`） | `Platform.isPhone`，老版本回退 `Platform.isMobile && !Platform.isTablet` —— 即「**是不是真手机**」 | **`isPhoneDevice` 全仓只有 1 个调用点**（`main.ts:377`，手机预览命令的 `checkCallback`）。**要不要用真机能力，代码里普遍直接判 `Platform.isMobile`**（抽屉路由 `main.ts:874`/`966`、打开系统文件夹 `snapshot.ts:156`、长按分流 `mobile.ts:109`） |

**三种适配手段**：

1. **布局靠 CSS 类，不靠媒体查询**：`applyPlatformMobileClass()`（`mobile.ts:18-20`，`main.ts:206`）给 `body` 加 `wt-mobile`；手机布局全部写成 `body.wt-mobile ...`（76 行 / 64 条规则，`styles.css:4488-4686` 是主区块）。**所以整个项目 `@media` 只有 4 个**（3 个 reduced-motion + 1 个 `hover: none`）。窄屏响应式另有 `@container` 3 处（宿主靠 `container-type: inline-size`，`styles.css:1478`）。
2. **抽屉靠 Obsidian 原生 split，不在 CSS 里**：`styles.css` 里**没有** `drawer` 字样。`openInMobileDrawer(type, side)`（`main.ts:905-922`）用 `getLeftLeaf`/`getRightLeaf` + `setViewState`，并且**会先清掉早期误开在中间编辑区的同类型 leaf**；启动时 `migrateMobileViewsToDrawers()`（`main.ts:924-960`，在 `onLayoutReady` 跑）做一次自愈。另外 `revealLeafCompat()`（`main.ts:890-902`）**用 `setActiveLeaf` 代替 `revealLeaf`**——因为 `minAppVersion` 是 1.4.0。
3. **长按菜单用捕获阶段吞掉后续 click**：`handleSuppressedClick`（`mobile.ts:46-54`）解决「长按弹出菜单后，紧随的 click 又顺手把文件打开了」。`bindLongPress` 450ms 触发、位移 >10px 取消；抑制槽是**单元素单次**语义（`mobile.ts:40`）。**必须用 `registerDomEvent` 注册**（`main.ts:481`）——历史上这里是模块顶层的 `document.addEventListener` 副作用，插件停用时无法移除会留下旧监听器。

### 3.4 字数统计的完整链路（最容易改错的地方）

```
                            ┌─ 编辑器输入 ──────────────────────────────┐
                            │ handleEditorChange                        │
                            │  · 程序化编辑（快照恢复/应用格式）→ 只重设基线，不计入
                            │  · 外部同步刷新（AI 改完 Obsidian 刷新编辑器）→ 已由 vault 路径统计过
                            │  · 新文件第一笔内容 → 整份算新增
                            └───────────────┬───────────────────────────┘
外部 AI/脚本直接改文件 ──► handleVaultModify ─┤
  （只触发 vault modify）   · externalModifyQueue 串行化，防异步竞态
                            ▼
                    applyDailyStats(file, delta, 计不计时长)
                            ▼
        dailyTotal / dailyGross / dailyDurationHistory / fileBaselines
                    ▼
                状态栏 + 侧栏 + 主页热力图
```

**必须记住的规则**：

1. **每日字数统计用净增口径**：`dailyHistory` 是净增（可正可负，删除会抵减）。今日目标、热力图、状态栏、主页与手机状态条显示的都是它——用户明确不接受「不负数」的毛新增口径（2026-10-18 移除了 `dailyGrossHistory` / `projectGrossHistory` 整条数据链路；旧 data.json 里残留的这两个键不再读写，无迁移必要）。
2. **外部修改必须串行**：AI 连续多次写入时若并发读盘会漏计或让基线倒退，所以走 `externalModifyQueue` 队列（`main.ts:186`、`1306`）。
3. **「写作时长」有 30 秒的空闲上限**：两次输入间隔超过 `MAX_IDLE_GAP_MS = 30_000` 即视为停止写作，这段间隔**不计入时长**（`main.ts:104-106` 注释：2026-08-13 由 120s 收紧为 30s，「避免停顿（喝水/切走/思考）被全额算作写作时间」）。**改时长统计别绕过这个阈值。**
4. **程序化编辑要按「编辑器 + 最终文本」精确匹配后忽略**（`pendingProgrammaticEdit`，`main.ts:1204`）；外部写入的内容要记下来供编辑器识别同步刷新（`lastExternalSyncText`）。
5. **切换统计模式必须先改模式再重建基线**，否则会拿「新模式计数 − 旧模式基线」得到巨大误差（`main.ts:794-819`）；番茄专注中也要同步重设番茄基线。

**基线档案**：`fileBaselines` 记录每个文件最近一次已知字数；`baselinesAt` 是「上次建立基线档案的时间戳」。启动时 `scanNewFilesOnLoad` 只对**上次退出后新建**的正文文件按整份内容计入当天，更早的文件只建档不追溯（`main.ts:1317` 起）。文件改名/移动要把基线一起搬（`main.ts:2461`），文件删除要清掉旧基线（`main.ts:614`）。

> **焦点无关原则**：侧栏/工具箱获得焦点时 `workspace.getActiveFile()` 会返回 `null`。所以快照、批注、统计都不能依赖「当前焦点」，而要用 `lastKnownPath` / `lastKnownText` / `currentMarkdownView()` 兜底（`main.ts:180-184`）。

> **读-改-写必须用 `vault.read`，不能用 `cachedRead`。** `cachedRead` 返回的是**可能过期的缓存内容**，用它做「读全文 → 改 → 写回」会把 Agent/其他工具刚写入的内容**覆盖掉**（这是踩过的坑）。`main.ts` 里现存的 4 处 `cachedRead`（`1306`/`1340` 周边统计、`1942` 复制干净正文、`2018` 定位锚点）**都只读不写回**，可以保留；但只要你的新代码打算**写回**，必须先 `vault.read` 拿最新内容。批注的读写路径（`commentStore.ts:58` 用 `vault.read`）遵守这条。

### 3.5 主题与配色的双层机制（改样式的核心约定）

> ⚠️ **先记这条会让人崩溃的坑：自定义属性必须挂在 `body` 上，不能挂 `:root`。**
> Obsidian 的 `--text-*` / `--background-*` 都定义在 `body`。如果你在 `:root` 里声明并引用它们（比如批注的 `--cmp-*` 令牌），`var()` **解析不到值 → 整条声明变成无效值 → 整条属性失效**。后果是「正文里的批注标记整片看不见，只剩一个孤零零的序号」。这个坑的结论就写在 `styles.css:5212-5214` 的注释里，**新增任何自定义属性令牌都请沿用 `body` 前缀**。

**令牌体系**：样式不直接用 Obsidian 变量画自己的界面，而是先定义一套 `--wt-*` 设计令牌（`--wt-paper`、`--wt-ink`、`--wt-accent`、`--wt-rule`、`--wt-card-bg`、`--wt-shadow`…），令牌值**按配色主题 × 明暗各给一套**，定义在选择器内：

```css
/* styles.css 片段（暖纸默认值写在 .theme-dark .wt-wb, .wt-sidebar, .wt-settings-page 等） */
.theme-dark .wt-wb, .theme-dark .wt-sidebar, .theme-dark .wt-settings-page {
  --wt-paper: #1d1a17;  --wt-ink: #ece4d6;  --wt-accent: #e07a5f;  ...
}
/* 换配色：body 上挂类，令牌整体换掉 */
body.wt-theme-cool      :is(.wt-home, .wt-wb, .wt-sidebar, .wt-settings-page) { ... }
body.wt-theme-cool.theme-dark :is(...)                                       { ... }
body.wt-theme-contrast  :is(...)                                             { ... }
```

组件样式只消费 `var(--wt-*)`；`styles.css` 中 `var(--wt-ink-)`/`var(--wt-accent*)`/`var(--wt-ink)` 等令牌被引用数百次。**新增界面元素 = 消费已有令牌，不要在组件里写死颜色。**

**首帧不闪（这个机制很绕，别拆）**：Obsidian 在**插件 JS 运行之前**就加载已启用的 CSS 片段，所以插件把当前配色的令牌写进 `.obsidian/snippets/wt-theme-tone.css` 并同步启用状态（`syncThemeSnippet`，由 `features/typographyModule.ts` 调用）：

- 暖纸（默认）→ 片段停用（内容只有一行注释）；
- 冷调 / 高对比 → 片段启用，且**给所有变量与 `background` 声明统一加 `!important`**，以压过 `styles.css` 里的暖色规则（含暗色下优先级更高的渐变背景），**不依赖选择器特异性**；
- 片段选择器**不能依赖 `body.wt-theme-*` 类**（那个类要等 JS 才加上），所以用 `body` 前缀 + `:is(...)` 抬特异性；
- ⚠️ **片段里的令牌必须与 `styles.css` 同名块逐字一致**。片段带 `!important` 且先于插件 JS 生效，会盖掉 `styles.css` 的同名令牌——只改一边等于没改（2026-10-18 高对比度换 Notion 风配色时踩过：`styles.css` 已改，片段还是旧的纯黑值，界面毫无变化）。`tools/checks/check-theme-palette.js` 逐令牌比对两边，反向验证见 §4.9；
- 双保险：`typography.ts` 还把配色缓存进 `localStorage["wt-theme-tone-cache"]`；`onload` 创建 `appearance.typography` 模块后，通过它的 `applyCachedThemeTone()` **在第一个 `await` 之前同步执行**，避免首帧闪成暖纸。
- 整个片段同步 try/catch 只 `console.warn`，失败降级为默认暖纸。

**排版注入**只用「CSS 变量 + body 类名」（`typography.ts`，由 `appearance.typography` 模块编排），**不动态创建 `<style>` 元素**——Obsidian 审核明确禁止。段首缩进是纯视觉 `text-indent: 2em`，不往正文写空格。

### 3.6 样式层的结构约定（展开见《样式与主题》）

`styles.css` 约 7,000 行、1,000+ 条规则，命名 `wt-<功能域>-<部件>`，状态类统一 `is-*`。
**改样式前先读 [`样式与主题.md`](样式与主题.md)**，那里有：分区结构、令牌体系（`--wt-*` 62 个 +
组件令牌 25 个）、影子体系、高对比度 Notion 皮肤、编辑器主题、番茄钟比例与宿主坑。

主文档只留三条**改样式前必须知道**的结论：

1. **追加式增长有结构性问题**：50 个选择器被声明多次（后者覆盖前者）；末尾有一整块
   「从 1.0.1 恢复」的裸选择器兼容回填（`styles.css:5736-5857`），**别当死代码删掉**。
2. **`!important` 共 79 条生效声明**，每条都有理由；新增前先读《样式与主题》§0 的口径。
3. **必须清除宿主默认样式**：Obsidian 给 `<button>` 的冷灰底与 `box-shadow` 会压在暖纸上「跳出来」，
   新面板里的 `<button>` / `<input>` / `<select>` 记得三连清（`border: 0; background: transparent; box-shadow: none`）。

### 3.7 ⚠️ 样式调试没有反馈回路（本插件最痛的工程约束）

> 样式层的完整知识（令牌、主题、手机端、宿主坑）见 [`样式与主题.md`](样式与主题.md)。

这不是比喻，是历史事实：**CSS 坏掉的方式全是静默的**，而开发时**看不到 Obsidian 的渲染结果**，反馈回路长达「一整个用户往返」——曾经一轮合并改动连环引爆 8 个新问题（丢了 `background: transparent` 导致按钮露灰底、丢了 `border` 导致状态胶囊没边框、`--wt-wb-hair`/`--wt-wb-wash` 变量没定义、属性 diff 显示「0 处差异」但视觉不同），全靠用户来回截图描述才定位。

而且**自动比对 CSS 极不可靠**（历史上连续误判 4 次）：
- 把 `.wt-settings-tab` 重写为 `.wt-sidebar .wt-settings-tab`（提升特异性）会被文本比对误判成「选择器丢失」；
- **同名 `:is()` 块会完全覆盖**后者：新加的批注样式块遮蔽了 1.0.1 的 17 个暖纸变量，**属性级 diff 显示 0 处差异，但视觉全变**；
- 把「新版没有某声明」当成删除，就会误删 `background: transparent` 与 `border`。

**所以：**
1. **不要用脚本"合并/恢复"整个 `styles.css`**。历史上正是这类操作把状态栏、日历、热力图的样式一起覆盖掉的。**要么整文件用 git 恢复，要么手工最小改动。**
2. 比对两份 CSS 时，**必须做到「选择器 + 属性」级别的 diff**，并逐条判断是「删除」还是「移动/提高特异性」；文本级比对会骗你。
3. 复查视觉时**不能只看桌面中央编辑区**——**中央编辑区宽度变化本身就会让主页/欢迎页看起来"样式变了"**（曾据此误判整轮）。
4. **测看不到的面板**：批注面板历史上同时存在三个实例、其中两个是 `display: none`，测到的那一个 `width=0`，导致整轮排查方向错误。**测 UI 前先确认"你看的是哪一个实例、它是不是隐藏的"。**
5. 桌面调试移动端布局时，在开发者工具 Console 里给 `body` 加 / 去 `wt-mobile` 类（见《样式与主题》§3）；不要把预览入口注册成命令，命令面板固定只保留四个入口。`src/mobile.ts` 的 `toggleMobilePreview()` 没有调用点、会被 tree-shake，别在文档里把它当入口。
6. **2026-10-18 起：改动渲染/布局前，先过一遍本地无头预览器**——`.wt-preview/harness`（在**测试库根目录**，不在本仓库内）。它用系统 Chrome 无头渲染**真实组件 + 真实 `styles.css`**（esbuild 打包 `src/` + `obsidian` stub），`node render.mjs` 一条命令出图，`node compare.mjs` 把截图与设计参考图按卡片高度归一化后并排/叠图并打印实测几何量。它**不能替代真机验收**（字体回退、Obsidian 变量都是近似值），但能在「一整个用户往返」之前抓住绝大多数尺寸与层级错误——番茄钟胶囊改版就是靠它逐版对齐的。
   ⚠️ 参考图是**第三方 App 的截图**，只放在测试库的 `.wt-preview/` 下，**绝不进版本库**（理由同 §6.1 的隐私护栏）。
7. **无头 Chrome 跑完必须自己收尾，否则会留下孤儿进程**（2026-10-19 事故）。headless 子进程一旦父进程退出，会被 launchd 收养成 `PPID=1` 常驻；macOS/LaunchServices 于是认为「Chrome 已在运行」，**用户点图标打不开浏览器**（本次是 5 小时 20 分的一棵进程树 + 191MB 临时 profile）。做法：临时 profile 统一放 `/tmp/wt-chrome-<名字>`；脚本用 `trap … EXIT` 兜底 `kill`；每轮删 profile。收尾自查只认可执行文件路径、别用 `grep "Google Chrome"` 计数（会命中自己的命令行）：
   `ps -axo pid,command | grep -- '--headless' | grep -v grep`（应为空）
   `ps -axo pid,command | grep -- '--user-data-dir=/tmp/' | grep -v grep`（应为空）

## 4. 开发规范与禁忌

### 4.1 红线禁忌（按事故严重度排序）

**禁忌 1 · 不要「顺手」大范围重写样式或界面代码。**
这是本插件**真实发生过的最严重事故**：某次改动把界面「改得面目全非」（主页左侧、欢迎页、按钮细节全变），最后只能从 git 1.0.1 回滚样式，再手工把新主题与批注功能合回去。**改样式只做外科手术式的最小改动**；要重构就先在 `_backup/` 留快照，并一次只动一块。另外注意：**中央编辑区宽度变化会让主页/欢迎页看起来"样式变了"**——先确认是不是布局宽度导致的错觉，再动 CSS。

**禁忌 2 · 不要把 `manifest.json` 的版本号随手抬到下一个大版本。**
社区插件发布必须保持 **`manifest.json` 的 `version` = git tag = `versions.json` 的键**，且三者同步。历史上曾把版本写成 `1.4.0`（应为 `1.0.2`），发布流程直接受阻——**根因是改错了字段：`1.4.0` 是 `manifest.json` 里的 `minAppVersion`，不是插件版本**。同一个文件里两个数字，改之前先看清字段名。`minAppVersion` 也要与 `versions.json` 一致。

**禁忌 3 · 不要把个人内容带进仓库。**

仓库公开在 GitHub。已 gitignore：`data.json`、`_backup/`、`main.js`、`*.map`、`.DS_Store`、`node_modules/`、`release/`。

**这条已经出过一次真实事故**：`src/main.ts` 与 `src/project.ts` 的示例注释里用了**真实作品名与角色名**，并随 3 个 release 提交推到了公开仓库（详见 §6.1 的隐私护栏）。**现在源码已全部脱敏成虚构名**（如 `P3-示例作品`），并装了三件护栏：`tools/release-check.sh` 体检、`.git/wt-blocklist.txt` 词表（**刻意放在 `.git/` 内、不进版本库**）、pre-commit 钩子。

- **写注释、文档示例、测试数据时一律用虚构名**，别图方便用真实作品名——那正是事故成因。
- 真实名词表在 `.git/wt-blocklist.txt`，**换机器 / 重建仓库后要重装钩子与词表**（`.git/` 里的东西 clone 不走），装法见 `tools/release-check.sh` 顶部注释。
- **提交署名里的作者邮箱是公开的**（历史上已公开），如果介意就换一个公开邮箱。

**禁忌 4 · 不要在编辑器里放跟随文字滚动的浮层。**
批注浮层被用户明确否掉两轮：*「会让编辑器内的批注卡片也跟着跳来跳去，看上去并不舒服」*→*「还是会跳，不如不要编辑器内的卡片，只保留侧栏的卡片」*。正文里只留**非滚动的**痕迹（底色标记 + 行尾脚注号），交互一律挪到侧栏面板与屏幕居中模态框。**任何新的编辑器内 UI，先假设它会滚动抖动。**

**禁忌 5 · 不要给同一个危险操作叠两道确认。**
删除批注曾同时有「按钮二次确认」和「弹窗确认」，用户得连点三次（*「我发现点完删除后，再点确认，它还会出来一个弹窗，再让我确认一遍」*）。现在的约定：**按钮 `删除 → 确认`（3 秒窗口）+ 删除后 6 秒内可「撤销」**，不再有弹窗。新增破坏性操作请沿用「一次确认 + 可撤销」，别叠。

**禁忌 6 · 不要直接改 `data.json` 的字段名/结构。**
用户数据里已经有真实历史统计（历史快照：**顶层 18 键**、`settings` 39 键、`dailyHistory` 34 天、`fileBaselines` 371 条、`dailyFileDeltas` 4 天；**只有 `dailyFileDeltas` 裁剪到 60 天**（`main.ts:2548-2552`），其余历史 map 无限增长）。读设置走**白名单合并**（只取 `DEFAULT_SETTINGS` 里存在的键，顺带清掉废弃字段如 `fontSize`），统计字段用 `|| {}` 兜底。删/改字段必须写迁移，并在注释里写明旧格式保留策略（参考 `main.ts:2598`「老格式如有历史数据则保留，不主动清空」）。

> ✅ **这里曾经埋着一个真 bug，2026-10-16 已修**：`loadPluginData` 的**旧扁平格式分支**里曾有 **17 个字段**写成 `DEFAULT_SETTINGS.xxx`（少了 `data.xxx ??` 前缀），后果是「从旧版本升上来的用户，改过的设置被默认值顶掉、并整文件覆盖写回 `data.json`，不可逆」。修法是在分支开头先 `legacyFlat = { ...data.settings, ...data }`，再用 `restoreFromLegacy(key)` 逐个取回。
> **这条现在有回归检查兜着**：`tools/checks/check-loaddata.js` 会拿 17 个非默认值跑一遍真实方法体，丢失就报警。
> **新增设置项时的正确写法**是 `data.x ?? DEFAULT_SETTINGS.x`（或走 `restoreFromLegacy`）；**别只给默认值、指望回头补**——当年就是漏了 17 行。

**禁忌 7 · 不要在 `onunload` 之外留下计时器、监听器与 body 元素。**
已注册的必须清：番茄钟定时器、快照 30 秒 tick、跨天检查定时器、`immersiveHintEl`、侧栏的 combo 菜单监听（`sidebar.ts` 的 `comboCleanups`）。`appearance.typography` 的 `EffectScope` 会移除自己写入的 CSS 变量与 body 类。**插件级 Vault / Workspace / DOM / 布局事件与定时器统一走 `EventScope`**；body 级监听至少要用 `registerDomEvent`，不要留下裸 `addEventListener` 或裸定时器。

**禁忌 8 · 侧栏/视图对象的方法要先判类型再调。**
踩过 `refreshComments is not a function`：侧栏 leaf 里的视图实例不一定是目标类，**必须逐项检查 `typeof x === "function"`**，否则一个可选方法的缺失会连带把「保存批注」这种无关操作一起弄失败（`main.ts:1563-1577`）。

**禁忌 9 · 原型类的 `display()` 可能被调多次。**
Obsidian 的 `ItemView.display()` 在视图重新显示时会被再次调用。**所有事件注册、资源创建都要幂等**（在 `display()` 里挂监听必须配对应的解除，或改用 `registerEvent`），否则会叠加监听与 UI。

**禁忌 10 · 不要给 Command + P 增加第五个命令。**
本插件的命令面板是**永久四入口白名单**，只允许「打开主页 / 打开工具箱 / 打开编辑台 / 打开设置」。新增功能、格式命令、批注操作、自检、调试入口、移动端预览、章节重编号、数据清理等都不得注册成 Obsidian 命令；应进入三个主页面、侧栏、右键菜单、设置页或编辑工具条。`tools/checks/check-commandsurface.js` 固定了命令 ID 与显示名称，`npm run verify` 会把第五条命令直接判成回归。

**禁忌 11 · 不要把 `tsc --noEmit` 跑不过的代码构建上线。**
本项目 `strict: true` 且当前干净。构建前跑一次类型检查；构建产物直接落到正在运行的插件目录（§1.1），构建出坏代码 = 插件当场坏。

### 4.2 必须遵守的约定

1. **输入法优先**：`composing` 期间不弹浮层、不 dispatch、不拦按键。**遵守这条的是**：工具条（`formatToolbar.ts:295`）、批注刷新（`commentDecor.ts:54`）、回车硬换行（`hardBreak.ts:39`）。**海明威模式是例外且相反**：它没有 composing 守卫，`transactionFilter` 反而要在 `input.compose` 时**放行**（`hemingway.ts:39-44`）——否则中文组词会被拦掉。
2. **判断「正文」一律用 `isDailyCountFile()` / `chapterPaths()`**，不要写路径关键词匹配。
3. **判断「内部路径」用 `isInternalPath()`**（任一路径段以 `.` 开头）。
4. **正文文本绝不被功能副作用改写**（批注/章纲/快照都在伴随文件里）。唯一例外是用户主动的格式命令；章纲在 `frontmatter` 模式下才会写 YAML（`outlineText.ts:260-263`、`364-397`）。
5. **伴随数据是「路径派生」绑定**：正文改名/移动**必须**同步迁移伴随文件（批注、章纲、快照、基线、以及 `data.json` 里以作品根目录为键的统计与封面），漏一个就出现「脱钩」。批注与章纲的迁移由各自的 `comments` / `outlines` 模块负责，不要在新代码里另写一套。
6. **章节编号 = 全书写法，改动前先出计划**：编号一律经 `planBookRenumber()`（`chapterOrder.ts`）规划，删除/插入/手动命令**共用它**（见 §4.10）。要点：
   - **保留原命名风格与补零宽度**（`第3章 雪夜` → `第2章 雪夜`；`第三章` → `第二章`）；
   - 编号本来就连续时**计划为空**，绝不去动一个正确的库；
   - 目标路径上站着**不参与编号**的文件（资料/番外/未命名稿）→ 标 `conflict` 跳过，**绝不覆盖**；
   - 执行顺序**按目标编号从大到小**（先腾出高位，避免半路撞名）；
   - 整卷删除要用 `deletingVolumePaths` 抑制逐章重编号（`workbench.ts`）。
   > ⚠️ 历史坑：旧实现是「从删除位置往下连减、**断号即停**」，所以编号一有间断就**一章都不改**（实测「1、3、5 删第3章」→ 重编号 0 章）。现已改为全书写法。
7. **装饰层不写文档**：批注标记/脚注号是 CodeMirror 装饰的产物、**不在文档文本里**，所以「一键复制干净正文」天然干净；若你的功能确实要往正文写记号（如 `**`），必须同步更新 `stripInlineFormatting`，否则字数统计虚增（`formatWrap.ts:329-335`、`wordcount.ts:56-58`）。
8. **焦点无关**：不要用 `getActiveFile()` 当作唯一来源，用 `lastKnownPath` / `currentMarkdownView()` 兜底。
9. **扩展不直接 import settings**：所属 Feature Module 读取设置后，通过 config 回调或运行时闭包注入；热更新由模块订阅，并在需要时调用 Editor Service 刷新。
10. **装饰重建必须显式触发**（`dispatchCommentRefresh`），并容错 `composing` 与已销毁视图。
11. **CSS 写在 `styles.css`**，用 `wt-` 前缀 + `--wt-*` 令牌；不动态建 `<style>`；自定义属性挂在 `body` 而非 `:root`（见 §3.5）。
12. **颜色/间距跟随令牌与主题**，不硬编码（现有硬编码色残留是历史债，别扩散）。
13. **数据变化后同步刷新界面**：`refreshSidebar()` / `refreshNow()` / 面板 `refresh()`；侧栏面板有「内容签名跳过重绘」与「`renderSeq` 代数丢弃晚到结果」两个防抖机制，照用。
14. **危险操作给结果反馈**：`Notice` 提示 + 可撤销窗口。

15. **插件级事件与定时器统一走 `EventScope`**：`main.ts` 使用主作用域，
    Host 为每个模块创建独立作用域，`MobileStatusBar` 也使用自己的作用域。
    `EventScope` 负责 Vault / Workspace / DOM 订阅、布局就绪回调、
    `setTimeout()` / `setInterval()`、幂等销毁和回调异常隔离。
    `FeatureContext.registrations` 的类型是 `FeatureRegistrationApi`，已从
    `HostRegistrationApi` 中移除 `registerEvent` / `registerDomEvent` /
    `registerInterval`；Feature Module 不得绕过 `EventScope` 注册这几类资源。
    Host 还处理了异步启动竞态：模块 `activate()` 未完成时 Host 被销毁，
    迟到结果不会再把模块标成 `active`，而是停用并清理后回写 `inactive`，
    同时停止启动后续模块。
16. **第一版不做通用事件总线**：设置变更仍由 Settings Service 的
    `subscribe()` / `publishChanges()` 负责，CodeMirror 事件仍归 Editor
    Service / 编辑器扩展生命周期，视图内部 DOM 事件仍归视图自身生命周期。
17. **事件所有权必须明确**：`outlines` 模块通过 `FeatureContext.events`
    统一订阅 Vault / Workspace 事件；`ChapterOutlinePanel` 自身只保留随组件
    生命周期清理的定时器，并继续使用销毁守卫：
    异步 `render()` 用 `renderSeq` 丢弃晚到结果，`openEditorModal()` 在
    `await` 后重新检查 `destroyed` / `editorModal`，销毁后不会继续回写 DOM
    或打开模态框。新模块不得直接使用 `.on()` / `.offref()` 注册插件级事件。
18. **别动用户的剪贴板**：调试「一键复制」这类功能时，**先读回确认再写**——历史上开发过程覆盖过用户正在用的剪贴板内容。

### 4.3 新增一类「跟随文档的伴随数据」

照 **`comments.ts` + `commentStore.ts`** 的模子写，必须实现：

| 必须项 | 说明 |
| --- | --- |
| `pathFor(docPath)` / `docPathForSidecar(path)` | 正反向路径换算；反向必须能识别「自己不是正文」 |
| `isXxxSidecar(path)` | 让 `isInternalPath`/作品识别/章节列表排除它（否则会被当成章节、计入字数） |
| `serialize()` / `parse()` | 纯函数、容错解析（字段顺序任意、缩进续行、未知字段忽略） |
| 缓存 + 失效 | `commentStore` 按源文档路径缓存；文件外部改动要失效 |
| 改名/移动跟随 | 源文档 renamed 时把伴随文件一起搬，**不覆盖目标位置已存在的文件**（`main.ts:2090`）；章纲同理会「脱钩」（`main.ts:602-603` 注释） |
| 删除源文档时的清理策略 | 明确跟删还是保留 |

再补两条容易漏的：

- **把「伴随文件」接进排除体系**：新后缀必须在**每一处**会被问到「这算不算章节/正文」的地方生效，漏一处它就会出现在章节列表或字数统计里。`.批注.md` 的防线按用途分两类，照这份清单核对自己的类型：
  - **新布局先靠目录排除**：`.wt-comments/` 是隐藏目录，`project.ts:86` 的 `isInternalPath` 直接排除；`outlineText.ts` 的 `isDraftPath` 也把 `COMMENTS_FOLDER` 显式列进排除表（与 `.wt-outlines` / `.wt-snapshots` 同列）。
  - **靠文件名排除的**（旧版/普通目录里的 `.批注.md` 仍走这条）：`outlineText.ts:26-39` 的 `isExcludedChapterName` **内置豁免** → 默认「不算章节」名单 → `project.ts:111-119`（跳过）→ `outlineText.ts:134-146` → `snapshot.ts:34`。
  - **靠路径/上下文排除的**（隐藏目录、内部路径）：`main.ts:1488-1491` 的 `isInternalPath`/`isDailyCountFile` → `commentDecor.ts:137`、`210`（`isSidecarPath` 判断）→ `main.ts:463`、`1633`、`1930` → `workbench.ts:316` / `home.ts:294`。

  ⚠️ 注意：`workbench.ts:316` / `home.ts:294` 是 `isInternalPath` 守卫，**对普通目录里的 `.批注.md` 不起作用**——真正挡住它的是第一类里的内置豁免。**别只加内部路径守卫就以为够了。**
- **协议抬头与解析器必须同改**，而且协议里要写**多行缩进示例**（历史上两者脱节导致整条批注被静默丢弃）。另外两条**别乱动**的格式细节：
  - `# 批注 · <标题>` 这一行的**标题级别其实无所谓**——条目抬头正则 `HEADER_RE`（`comments.ts:567`）只在「批注」后**紧跟数字**时才匹配（实测 `## 批注 1` / `### 批注 1` 匹配，`# 批注 · 第1章` 与 `## 批注 · 第1章` 都不匹配），安全性来自中间的 ` · ` 分隔符而非 `#` 的个数。**真正要守住的是「别让标题行长得像条目抬头」**。
  - 字段值多行用**两格缩进续行**（`writeField:523`），解析时去缩进拼回；这是 Agent 手写回复时最容易写坏的地方，所以协议抬头里必须给例子。

### 4.4 新增一个面板 / 浮层

**第一步先决定「挂在哪」，这决定了你能不能直接用令牌**：

| 挂载位置 | 能不能用 `--wt-*` | 做法 |
| --- | --- | --- |
| 四个主容器内部（`.wt-home` / `.wt-wb` / `.wt-sidebar` / `.wt-settings-page`） | ✅ 能，**六套**配色（暖纸/冷淡/高对比 × 明暗）自动生效 | 直接消费令牌 |
| `document.body`（浮层 / 菜单 / 常驻条 / Toast） | ❌ **取不到页面令牌**（`styles.css:5022` 明写） | 二选一：① 像 `.wt-combo-menu` 那样在自身规则里定义 `--wt-menu-*` 并配 `.theme-dark` 覆盖；② 像 `.wt-mbar` 那样用 Obsidian 原生变量，**并按 `body.wt-theme-cool` / `body.wt-theme-contrast`（× `.theme-dark`）逐套补映射**（`styles.css:5021-5120`） |

**其余检查项**：

- **先判断它会不会滚动抖动**（禁忌 4）。会 → 放侧栏或居中模态框，不要跟文字。
- 挂侧栏：照 `sidebar.ts` 的标签页 + `wt-tb-card`；面板本体写成独立类（如 `CommentPanelBody`），带 `destroy()` 与内容签名。**只做一处，不要再注册独立视图**（历史上同一能力有两套实现）。
- **面板里渲染 Markdown**（`chapterOutline.ts` 的章纲阅读态）：用公开 API
  `MarkdownRenderer.render(app, md, el, sourcePath, component)`，**不要 `innerHTML`**。
  每次渲染 `new Component()` + `load()`，切内容/切模式/销毁时 `unload()`；否则链接、
  嵌入和悬停预览挂上去的监听器不会释放。`sourcePath` 传**所属正文章节路径**，
  `[[双链]]` 与相对图片才会按章节所在目录解析。渲染是异步的，用序号
  （`previewSeq`）丢弃过期结果。
  双态切换只重画主内容区（顶栏模式按钮保留），别让 `blur` 和按钮 `click` 各切一次——
  **顶栏按钮**（模式/放大）都在 `mousedown` 里 `preventDefault()`，
  否则编辑态点一下会先 blur 退出、click 再执行，同一内容写两遍、旧章节还闪一次。
  外部刷新（Vault 事件/设置热更新/编辑台或弹窗写同一章纲）在编辑态**只挂起不重建**
  （`pendingReload`），保存后回阅读态再统一 `render()`；同文件同内容的保存在途时
  复用同一个 Promise（`inflightSave`），避免 blur + click 各写一次。
  阅读态里的**任务列表复选框**只是渲染结果（没有可回写的正文文件），要拦掉 click
  的默认勾选，否则用户会以为勾选生效。
- 浮层挂 body + `position: fixed`：照 `formatToolbar.ts` 的三件套（`requestMeasure` 里读坐标、手机端 `interacting` + `pointerup` 捕获、`mousedown preventDefault`），`destroy()` 里移除 DOM 与 document 级监听。**`overflow:hidden` 的容器里不要放需要溢出的浮层**（会被裁剪），挂 body 或用 fixed 定位；滚动/缩放窗口时要自动关闭避免错位（`sidebar.ts:157-163`、`229-248`、`304-309`）。
- **命名**：一律 `wt-<域>-<部件>` + `is-*` 状态类，**不要用 `.panel` / `.card` / `.menu` / `.list` 这种泛化名**（会撞 Obsidian 原生与第三方主题）。
- **作用域**：所有选择器带 `.wt-` 或 `body.wt-*` 前缀；要压过原生控件用**父级前缀提高特异性**，别用 `!important`（反面教材：末尾那块「从 1.0.1 恢复」的裸选择器就是特异性收窄后不得不做兼容回填）。
- **清除宿主默认样式**：`<button>`/`<input>`/`<select>` 三连清 `border: 0; background: transparent; box-shadow: none`。
- **移动端**：布局差异写进 `body.wt-mobile` 段（**不要写 `@media (max-width: …)`**）；底部固定元素带 `env(safe-area-inset-bottom, 0px)`；触控目标 ≥44–46px；「悬停才显示」的控件用 `@media (hover: none)` 补常显；分支用 `isMobileUI()`（布局，含桌面预览）还是 `Platform.isMobile`（真机能力）要分清。面板若要进手机抽屉，走 `openInMobileDrawer` 并在 `migrateMobileViewsToDrawers` 里登记。
- **隐藏态**统一用 `.is-hidden` 类，不要内联 `style.display`。

### 4.6 必要的可观测性：自检能力（不进命令面板）

排查「为什么没反应」不要靠猜。插件保留格式工具条、批注和统计三套诊断数据与报告构建能力，但**不再把自检注册成命令**。命令面板是**永久产品约束**：只保留「打开主页 / 打开工具箱 / 打开编辑台 / 打开设置」四条，也就是“设置 + 三个主页面”。任何后续开发者都不得以调试、快捷操作或新功能为理由新增命令；`check-commandsurface.js` 会固定 ID、显示名称与数量。

| 报告类型 | 排查什么 | 诊断数据 |
| --- | --- | --- |
| 格式工具条 | 选中文字后工具条不出现 | `formatToolbarDiag`（`formatToolbar.ts`） |
| 批注 | 正文里批注标记/脚注序号不出现 | `commentDecorDiag` + `commentIoDiag`（`diagnostics.ts`） |
| 字数统计 | 字数/时长/目标不更新 | `statsDiag`（`diagnostics.ts`） |

**设计要点（照抄这个模式）**：把「为什么没走到那一步」的**每条判据各自计数**，而不是只记一个总数。比如批注会分别记「总开关关闭 / 拿不到路径 / 是批注文件本身 / 缓存未加载 / 这篇没有批注 / 定位全失败」，加上 `locateAll` 的定位方式分布与耗时——**一眼就能看出卡在哪一步**。报告末尾还有一节「怎么读这份报告」，把每条计数对应的处置写给人看。

**性能埋点也在这里**：`locateAll`（批注定位，每次输入都会跑）与状态栏刷新的**最近/最大耗时**都在统计自检报告里。2026-10-16 之前这条热点只是读代码推测的，现在可以直接测。

**新增容易「静默不生效」的功能时，照这个模式补诊断数据与回归检查，不要再加命令入口**。**并且别把埋点删掉**——埋点被删掉不会让任何检查失败（这是实测过的盲区），所以专门有一个源码级守卫 `tools/checks/check-hooks.js` 盯着这些调用点；`check-commandsurface.js` 则盯住四命令白名单。

**通用 Diagnostics Service 与领域诊断分层**：

| 层 | 位置 | 负责什么 |
| --- | --- | --- |
| 通用状态容器 | `src/services/diagnosticsService.ts` | 计数、耗时聚合（次数/最近/最大/总计）、最近值、有限错误历史、模块三态快照 |
| Host 投影 | `src/host/pluginHost.ts` | 把模块 `active` / `failed` / `inactive` 与启动、停用、清理错误写进 Diagnostics Service |
| 领域报告 | `src/diagnostics.ts` 与功能模块 | 批注、统计、格式工具条等面向人的报告和既有埋点 |

`DefaultDiagnosticsService` 不依赖 Obsidian，`snapshot()` 返回完全脱离内部状态的
副本。模块通过 `FeatureContext.services.diagnostics` 记录结构化事实；Host 是
模块生命周期状态的唯一来源，不把状态判断下放给 Service。旧
`src/diagnostics.ts` 继续承载领域报告，`formatToolbarDiag` 在第一阶段也留在

三个可复用的手法（`tools/checks/_harness.js` 里已封装）：

| 办法 | 适用 | 做法 |
| --- | --- | --- |
| **单独编译纯模块** | `comments.ts`、`wordcount.ts`、`project.ts`、`diagnostics.ts`、`commentStore.ts` | `esbuild <模块> --bundle --format=cjs --external:obsidian`，编出来直接 `require`。**优先用这个** |
| **抽真实方法体跑** | `main.ts` 里的大方法（如 `loadPluginData`） | 按符号 + 花括号配平抽出方法体 → esbuild 类型擦除 → 注入桩后执行。**逻辑一行不改**，结论可信 |
| **桩掉 `obsidian`** | 依赖 `App`/`TFile` 的类（如 `CommentStore`） | 覆盖 `Module._load` 返回最小桩；再用假 `vault`（Map 驱动）跑 |

**⚠️ 关于「要不要先 build」**：用**编译模块**做检查的不依赖产物；但 `check-loaddata` 抽的是 `main.ts` 源码、`check-hooks` 读的也是源码。所以 `npm run verify` 验的是**源码**，不必先 build（`npm run release` 里会按 check → verify → build 的顺序跑全）。

> 早先 `check-commentstore` 是从 `main.js` 切段落的，一旦 `commentStore.ts` 新增内部依赖（比如引入 `diagnostics`）段落就缺模块、检查直接崩。**已改成编译整个模块**——更健壮，代价是验源码而非产物，而源码与产物的一致性由 `npm run build` 保证。

**三个必须记住的注意点：**

1. **先装桩再编译/require**。编译产物在 `--external:obsidian` 下会真的 `require("obsidian")`，桩晚一步就报 `Cannot find module 'obsidian'`。
2. **写断言时先确认自己模拟的事件序列与 Obsidian 一致**。我第一次测批注缓存时漏了 `create` 事件，把"修复没生效"误判了一轮——真实流程里插件是靠 `main.ts:560` 的 create 处理器失效缓存的。
3. **文本级检查（正则）要匹配「真实的调用形态」，别假设标识符在行首。** 写 `^\s+foo\(` 看似稳妥，实际会漏掉 `if (reason) foo(...)`、`return foo({`、`void this.foo(` 这些最常见的写法——`check-hooks.js` 就因为这个原因**静默匹配不到 4 个埋点**，当时还误判成「全角空格 U+3000 作祟」（**那是错的：JS 的 `\s` 是匹配 U+3000 的**，实测 `/\s/.test("\u3000") === true`）。正确做法是照着源码里的实际片段写（如 `if \(reason\) commentSkip\(`），并**先跑一次确认匹配得上**。
   > 排查时的另一个陷阱：用 `node -e '...'` 传正则时**shell 会吃掉反斜杠**，`\s` 会变成字面 `s`，于是你以为在测正则、其实测的是别的东西。**把测试写成文件再跑。**

**这些检查验证的是逻辑**，验证不了渲染、布局、主题、输入法、移动端——那部分只能进 Obsidian 手动点（见 §4.7）。**新增一项检查时，顺手做一次反向验证**（把修复改回坏的样子，确认检查会报警），否则你不知道它是不是永远绿。这个习惯已经抓到过两次假绿：一次是断言顺序错（先 `load` 再断言缓存失效，等于自证），一次是 `includes("commentSkip(")` 命中了函数**声明**。

**shell 脚本的一个本地陷阱**：macOS 自带 bash 3.2，`"$VAR）"` 这种「变量紧跟中文标点」会被解析成变量名的一部分而报 `unbound variable`。**变量一律写 `${VAR}`**。这个坑在本仓库的脚本里出现过两次。

### 4.10 章节编号（全书连续，跨卷）

**编号是「全书阅读顺序」，不是「卷内序号」。** 章节按卷拼接成阅读顺序
（`allChapters()` 就是各卷依次拼接），编号 = 在该序列里的位置（从 1 起）。

规划与执行都在一处，别另写一套：

| 环节 | 位置 | 说明 |
| --- | --- | --- |
| 规划（纯函数） | `chapterOrder.ts` 的 `planBookRenumber(chapters, existingPaths)` | 返回**只含要改的条目**，按目标编号倒序 |
| 执行 | `workbench.ts` 的 `applyBookRenumber(interactive)` | 删除后、插入后、手动命令都调它 |
| 手动入口 | 卷右键菜单「全书章节重编号…」 | `interactive=true` → **先弹预览确认** |

**新建章节只有一个入口**（2026-10-16 简化）：顶部「+ 新章节」（手机端是右下角主按钮），
永远落在**最后一个有章节的卷**。卷头的「+」按钮与卷右键菜单的「在本卷末尾新建一章」**都已移除**——
它们会拿「全书最大章号 +1」塞进指定卷，于是第1卷拿到「第3章」而第2章在第2卷，顺序与编号立刻对不上
（用户报的正是这个）。**要在中间插章**请用章节行的「在下方插入一章」，那条会把后面的编号顺延。

**不参与编号的章节**（规划函数里显式排除，改动时别放宽）：
序章 / 楔子 / 引子 / 番外 / 后记 / 尾声（`parseChapterName` 给出的 number 是 0 或 null）、
认不出编号写法的文件名、以及作者用 frontmatter `sort_index` 显式定制顺序的章节
（重新编号会跟那个定制对冲，所以整项跳过）。

**`existingPaths` 必须从 `app.vault.getAllLoadedFiles()` 传**：
规划函数只有拿到「库里的全部路径」，才能判断目标路径上是否站着**不参与编号**的文件。
不传的话，与资料/番外撞名的情况检查不到，改名会覆盖别人的文件。

**安全约定**：认不出的写法不硬改；撞名跳过而不是覆盖；单章改名失败不中断其余
（重编号是幂等的，再跑一次即可）。

### 4.11 什么时候写 spec

2026-10-20 起按 [`specs/README.md`](../specs/README.md)：**实现之前需要作者确认的改动才写 spec**，
也就是新增 / 删除功能或入口、改 `data.json` 结构 / 设置项 / 默认值、用户会察觉的行为变化、换肤。
修 bug、重构、补检查不写，提交信息写清现象 / 根因 / 怎么验证。

- 一个 spec 是一个文件 `specs/NNN-slug.md`，六节：一句话 / 为什么 / 做什么 / 不做什么 / 怎么算完 / 记录。
- 状态只有 `draft` → `done`（或 `dropped`）；作者确认前不写实现代码，范围变了先改 spec。
- 「怎么算完」每条以「自动：」（指向 `tools/checks/check-*.js` 或白名单 npm 命令）或「人工：」（进 Obsidian 的具体路径）开头。
- `check-specs.js` 只守形式，在 `npm run verify` 里；发布不因 draft 拦截。
- 收尾时把新知识沉淀回本文 / 架构说明 / `AGENTS.md`，再改 `status: done`。
- `specs/archive/001`–`005` 是 2026-10-19 旧流程（三件套、六状态、宪法）的冻结记录。

### 5.2 已修复但仍易复发的坑（按技术面）

**批注锚点的语义细节（2026-10-16 补检查时摸清，之前文档没写）**

- **零宽锚点**：只有 `head` 活着（`tail` 不足 4 字）时 `from === to`，`commentDecor` 要求 `to > from` 才画底色 → 这种批注**定位成功但正文里只有脚注号、没有底色**，容易被误判成「批注没生效」。（实测钉住）
- **段落层「整段紧凑匹配」在 `quote` 非空时基本不可达**：`compact(quote) ⊆ compact(paragraph)`，整段能匹配上时 `quote` 必先被 fuzzy 层命中。只有「无原文的整段批注」或伴随文件被手改时才走得到。
- **空光标夹在 `**` 中间按斜体 = 顺手取消加粗**（`他**看雪。` → `他看雪。`）；`****` 中间按加粗会一次删掉四颗星，而代码注释写的是「删掉一层」——重复字符记号下 `[from-L, to+L]` 覆盖整个 run，**注释与实现不一致**。
- **字色同色是「两段」改动**（开、闭标签各一段），异色是「一段」。`changes` 的段数随场景变化，**调用方不能假设恒定**。
- **「格式记号不计入字数」有一个刻意例外**：`* * *` 在 webnovel 模式仍记 3 字（那是作者写的分隔线，不是记号），`* 列表项` 同理——`stripInlineFormatting` 的斜体规则要求星号后紧跟非空白非星号，就是为这两条。
- **术语不统一**：§3.2 写「锚点定位五层」，`comments.ts` 与检查里写「四层」（`present`/`exact` 都算精确命中，实际是 **4 层 5 种 `via`**）。读代码时以 `via` 的 5 个取值为准。

**坐标与滚动**

1. CM6 更新期间不许读布局，`coordsAtPos` 会抛异常 → 一律 `requestMeasure({read})` 延后（`formatToolbar.ts:224-239`）。
2. 气泡先加 `is-visible` 再量尺寸，否则量到 0；上下翻转 + 四边 8px 夹取。
3. 手机端点按钮会让编辑器失焦 → `interacting` + `pointerup` 捕获 + `mousedown preventDefault` 三件套。
4. 段落高亮会把标题/列表吸成一大段 → 独立 Markdown 块特判（`src/typewriter.ts` 的 `paragraphLineRange()`）。
5. 打字机底部留白压不过 Obsidian 写在 `.cm-content` 上的**内联** `padding-bottom` → 只能用 `!important`（`styles.css:4802`）。
6. 信纸横线用固定 px 会在标题字号变化后错位 → `background-size: 100% 1lh` + `background-origin/clip: content-box`。
7. 沉浸模式要隐藏左右栏/ribbon/tab/titlebar（`body.wt-immersive`），且**进入沉浸会临时强制打开打字机模式，退出必须还原**（`main.ts` 的 `setImmersiveMode()`）。

**CSS 层级与主题**

8. 工具条刻意放 `document.body`、**不进** `.wt-*` 主题作用域，用 Obsidian 原生变量——为了跟系统气泡一致。
9. 配色片段要压过插件自带暖色规则与暗色渐变 → 生成时统一注入 `!important`；片段选择器不能依赖 JS 才加的 body 类。
10. 首帧闪暖纸 → `localStorage` 同步缓存 + snippet 文件双保险。
11. Obsidian 审核禁止动态 `<style>` → 排版只能改 CSS 变量 + body 类名。
12. 选中色跟主题串味（高对比度下跳紫）→ 只覆盖 `.cm-editor` 的 `--text-selection`，不动全局设置。

**装饰与选区/撤销栈**

13. **块级装饰不能来自 `ViewPlugin`（会抛 `RangeError`），必须 `StateField`**（`commentDecor.ts:7-10`）。
14. 拼字期间 dispatch 会打断拼音 → `composing` 时 400ms 重试。
15. 状态字段 `create` 时 `editorInfoField` 可能未就绪 → try/catch + loader 稍后补刷新。
16. 拖动选择被批注的文字会误跳侧栏 → mousedown/mouseup 组合 + 位移 ≤4px + 600ms 窗口。
17. 数据变化不会自动重建装饰 → 必须显式 `dispatchCommentRefresh`。
18. 脚注号 widget 用 `side: 1`，`eq()` 要覆盖 `toDOM()` 用到的每个字段（`id`/`status`/`via`/`content`/`reply`），否则复用旧 DOM 会让 tooltip 停在旧内容（曾漏过 `content`，已修）。
19. 批注标记是**装饰层产物、不在文档文本里**，所以「一键复制干净正文」天然干净；脚注号还要 `user-select: none` 防止被一起选中。

**统计与数据**

20. 「算不算正文」别用路径关键词 → 用作品索引的章节集合（旧的会误纳 `.wt-outlines` 镜像章纲、漏掉按卷分目录的长篇）。
21. 切统计模式必须**先改模式再重建基线**，否则误差巨大。
22. 外部 AI 写入要串行排队，否则漏计/基线倒退。
23. 每日字数统一用**净增口径**（可正可负）；别再加回「不负数」的毛新增链路，用户不接受删减被隐藏。
24. `workspace.getActiveFile()` 在焦点位于侧栏时为 `null` → 一律用 `lastKnownPath` / `currentMarkdownView()` 兜底。
25. 侧栏刚 `setViewState` 时 DOM 还没建好 → `reveal` 立即失败要**延迟重试**（`main.ts:1907-1912`）。
26. 番茄专注中，外部字数变化要同步进番茄基线，否则 AI 的增删会被算进本番茄字数。

**输入法与按键**

27. 回车即新段落必须跳过：输入法拼字中、fenced code block 内、空行、块级语法起始行（`>` `-` `1.` `#` 表格 `|` 分隔线）。
28. 标点辅助的双右括号重复（`（内容））`）→ 输入闭合符时若右侧已是同一字符则只移动光标。
29. 海明威模式要允许「组词时替换末尾已有区间」（先插 `n` 再把末尾换成 `ni`），否则输入法候选确认会被破坏。

**性能**

30. 工具条每次视图更新都刷新，但重活延后到 measure 阶段；诊断探针专门统计 listener 触发次数以排查「update 有没有被调用」。
31. 批注装饰只在 `docChanged` / 显式刷新 / 换文件时重建，`locateAll` 对全文一次性建索引后批量定位。
32. **潜在热点（未解决）**：超长文档每次输入都会重跑 `locateAll`（`tr.docChanged` 分支无节流、无视口裁剪）。改批注性能时从这里入手。
33. 长列表刷新要保滚动位置（编辑台「只同步高亮不重建列表」，搜索时不抢滚动位置）；主页换页动画在后台刷新时不重放。
34. **滚动与坐标的配合**：批注的「上一条 / 下一条」曾无法自动跳转，原因是**从未调用滚动**——`coordsAtPos` 对**视口外**的位置不返回有效坐标。**规则：先把目标滚进视口（`scrollIntoView`）再读坐标**；已在视口内就不要滚（否则会来回抽动）；且必须让路给 `requestMeasure`（更新期间读布局会抛异常）。

**测试与自测手段本身的坑**

35. **测试脚本自己会骗人**：历史上临时写的 CM6 mock，`StateEffect` 的形状是"编的"（与真实不符但断言全过）；测试 harness 的正则因 `lastIndex` 残留**串味**，导致同一断言时对时错。**用 mock 测 CM6 时，先验证 mock 的行为与真实 CM6 一致**，别让"全绿"给你假安全感。
36. **测不到隐藏的面板**：三个批注面板实例并存、两个 `display:none`，测到的那个 `width=0`。先确认测的是哪个实例、是否可见。
37. **CSS 变更无法在 Obsidian 里自动验证**（没有截图能力，也没有 DOM 断言）——见 §3.7，这是本插件最痛的工程约束，务必用「最小改动 + git 整文件恢复」而不是脚本合并。

**基线产生"假数字"的确切历史 bug**

38. **还不知道当前文件时就产生增量** → 会拿「上一个文档」的基线做差，凭空多出几千字（`statusbar.ts:241-246` 注释）。
39. **把基线写到空键上** → 以前 `currentFilePath` 还没建立时基线被写到空路径键上，之后又拿这个键里的（别的文档的）字数做差，**凭空产出 ±几千的假数字**（`statusbar.ts:385-387`）。**现在的规则：空路径一律不记基线。**
40. **重启/跨天把整章当成新写的** → 所以启动时要载入上次会话留下的基线（`statusbar.ts:328`）。

**样式层已修但容易复发的坑（续）**

41. **弹窗尺寸别用 JS 写 inline style** → 快照对比弹窗原由 JS 直接写 `style`，现改为 `.modal.wt-diff-modal` 类（`styles.css:4795` 横幅注明）。同理隐藏态用 `.is-hidden` 类，**不要内联 `style.display`**（旧的 `style.display = ""` 恢复方式不可靠，历史备份里可见这次改写）。
42. **Obsidian 1.14 改了设置页下拉的实现**：不再是原生 `<select>`，也不一定带 `.dropdown` 类，而是 `<button class="combobox-button">`。写相关样式要**三种选择器都覆盖**，别只挑一种（`styles.css:4317-4335`）。
43. **快照对比要临时关掉海明威模式**：否则恢复动作会被 `transactionFilter` 拦掉（`snapshotDiff.ts` 的 `replaceEditorText`）。
44. **触屏没有 HTML5 拖拽**：桌面用 `draggable` 拖动分卷，手机端必须改用长按菜单里的「移到…」（`workbench.ts:1274-1275`）。
45. **移动端不支持打开系统文件夹**：`Platform.isMobile` 时给 `Notice` 提示（`snapshot.ts:156-159`），不要调用 Electron API。
46. **快照对比窗不要为了「标色」往正文塞 span**：一旦把每行包进 `<span>`，选中复制就会带上多余换行，粘贴到正文里等于污染。用 CSS Custom Highlight API 只注册 Range；`::highlight()` 的四个名字必须与 `snapshotDiff.ts` 的 `HIGHLIGHT_NAMES` 逐字一致，改一个就要两边一起改（`check-snapshotdiff.js` 会拦）。
47. **`contenteditable="plaintext-only"` 是快照右栏能「像编辑器」的关键**：普通 `contenteditable` 回车会插 `<div>`，`textContent` 直接丢掉换行；plaintext-only 下换行是纯文本，`textContent` 与显示完全一致（无头 Chrome 实测：回车后子节点仍全是文本节点）。
48. **弹窗里的 Cmd/Ctrl+C 会被 Obsidian 吞掉**：Obsidian 的复制命令作用于编辑器，焦点在 Modal 里时按 Cmd+C 什么都不发生。快照对比窗在 `document` 上以捕获阶段接管 Cmd+C / Cmd+A，但**只在选区落在两栏内时**才处理；左栏不可编辑、点空白处不产生选区，所以另记 `lastPointerPane` 兜底 Cmd+A。
49. **自动保存不要每次都存备份快照**：快照写回前会先 `snapshotFileSilently()` 备份当前版本，这是为「手动应用一次」设计的。接上自动保存后如果照搬，一次对比会话就会生成几十份快照、把 `snapshotMaxPerFile`（默认 20）挤光，用户真正的历史版本被自己挤掉。做法：会话级 `backedUp` 标记，只在第一次写回时备份。
50. **自动保存的撤销粒度由空闲阈值决定**：写回只能整篇替换，阈值 1 秒 ≈ 「撤销回到刚写完的那一句」。想更快保存就得接受撤销变碎，这两者不可兼得。
51. **编辑台只保留全书搜索，不要再加回「替换」**：Obsidian 编辑器自带搜索替换（Ctrl/Cmd+F / Ctrl/Cmd+H）已经覆盖改字场景，插件里再养一套等于重复入口；而且它是编辑台里**唯一会直接改写全书正文**的功能（一次「全部替换」可跨文件改写，要自己承担确认与撤销语义）。保留的搜索是**跨全书**的：正文模式扫全部章节、设定模式扫全部资料，给命中片段与「全书 N 处」计数，并与编辑器内的单文件查找不是一回事。`tools/checks/check-workbench-search.js` 同时守「搜索还在」与「替换不在」（SPEC-004）。
52. **颜色令牌只挂在四个页面上，弹窗里取不到**：`--wt-ink` / `--wt-card-bg` / `--wt-rule` / `--wt-wash` 这些**颜色**令牌定义在 `:is(.wt-home, .wt-wb, .wt-sidebar, .wt-settings-page)`（`styles.css:6441` 一带），`body` 级块（`styles.css:6263`）只有圆角与字号。任何挂在 `body` 下的 UI（`.modal-container` 里的弹窗、编辑器里的浮出工具条、批注标记）**直接 `var(--wt-ink)` 会解析失败**——表现不是「颜色有点不对」，而是底色/描边整条声明失效、文字回退继承。做法：要么像 `.wt-diff-modal` 那样改用 Obsidian 变量（`--text-muted` / `--font-ui-small`），要么在容器上自带一套（读者手机预览的 `.modal.wt-phone-modal` 就是这么做的）。2026-10-19 写读者手机预览时，由渲染验证环节按令牌作用域排查发现（弹窗里的颜色引用会整条失效）。
53. **读者手机预览是「纯文本阅读器」，不是第二个渲染预览**：它显示的就是「一键复制纯净正文」那份文本（共用 `cleanChapterText()`），`#` / `**` / `-` 会原样出现——因为平台上的读者看到的就是这个；别为了好看改成 `MarkdownRenderer`，那会掩盖上传后的真实样子。机身内三种底纹是**阅读器自己的配色**，刻意不跟随 Obsidian 主题；入口只在桌面端（真机不显示），预览全程只读（`tools/checks/check-mobilepreview-module.js` 守这些边界，SPEC-005）。
54. **今日数值属于 `activeDay`，不是「此刻的日期」**：`dailyTotal` / `dailyDurationSeconds` 只在 `ensureCurrentDay()` 里切天，所以凡是把它们写进 `dailyHistory` / `dailyDurationHistory` 等按日期键的地方，**键必须用 `activeDay`**（或先 `ensureCurrentDay()` 再取键）。旧实现在 `savePluginData()` 里按实时日期 `todayStr` 回填，零点后、跨天结算前的任何一次保存（2 秒防抖、睡眠唤醒后点按钮、卸载）都会把昨天的总数写进今天，今天随后从昨天的总数起算。`tools/checks/check-day-rollover.js` 用假时钟跑真实方法守住这条。

### 5.3 反复复发的对抗性问题

**为什么「批注」是重灾区**：它同时踩了五个技术面——① 编辑器内浮层随滚动抖动（用户否了两轮）；② 锚点在 Agent 改稿后必然漂移（需要五层定位 + 手动重绑）；③ 装饰重建必须显式触发且要容错拼字/销毁；④ 侧栏面板重绘与跳转时序冲突；⑤ 危险操作确认流程措辞与交互反复调整。**任何"多个 Agent 都改不好"的功能，基本都具备"UI 层 + 数据层 + 时序 + 用户手感"四重耦合这个特征。** 改它之前先把 §3.2「批注的渲染」整节读完。

**为什么「样式」反复回退**：令牌体系（`--wt-*`）+ 主题三色 × 明暗两套 + 移动端 `body.wt-mobile` + Obsidian 自带主题变量 + 内联样式覆盖，五个变量维度相乘。**碰样式前先确认哪个维度在起作用**（用浏览器开发者工具看 `--wt-*` 的实际取值来源最有效），否则「修好这里坏那里」。更底层的困难是 §3.7：**CSS 坏掉是静默的，你看不到 Obsidian 的渲染**，所以只能靠「最小改动 + git 整文件恢复 + 请用户确认视觉」这条慢回路。

**为什么「清理入口」这种"简单任务"也会出事**：历史上出现过「为了简洁删掉多余入口，结果把某功能的所有入口都删光」；同一轮任务里还发生过「理解错需求方向，删错了东西」（用户原话：*「编辑器里的新建批注我要用的，但是侧栏里的不要，你理解错了我的想法」*）。**涉及删除的改动，先把"这一功能现在有哪几条入口/哪几处实现"列出来，删除后立刻验证功能仍可达；需求含糊时先问清，别猜。**

**为什么「统计数字」偶尔对不上**：输入路径有四条（编辑器输入 / 程序化编辑 / 外部 AI 写盘 / 启动补建），每条都要正确区分「算不算、算谁的、算不算时长」。排查时先看 `dailyFileDeltas`（每日各文件明细，专门为这个问题留的）。

**为什么「移动端」特别难**：移动端布局不是媒体查询自动适配的，而是 `body.wt-mobile` + 76 条 CSS 规则**手工铺的一套布局**；多视图并存时还有实例问题（历史上三个批注面板同时存在、两个是 `display: none`，测的那个 `width=0`，整轮排查方向都错了）。抽屉式面板与移动状态栏是**保留的两个备份迭代方向**（`_backup/2026-10-13-mobile-drawer/`、`_backup/2026-10-13-mobile-statusbar/`，后者在 `src/` 里多出 `mobileStatusBar.ts`）。**改桌面端样式时默认会顺带影响手机端**；桌面调试在 Console 里给 `body` 加 / 去 `wt-mobile` 类（见《样式与主题》§3），不要把入口注册成命令。

| 症状 | 先看哪里 |

### 6.6 官方审查规则（本地复刻 + 发布闸门）

社区插件后台有一套自动审查。仓库里装了 **`eslint-plugin-obsidianmd`** 把同一套规则复刻到本地：

```bash
npm run lint:review   # 完整报告（含 @typescript-eslint 噪音）
npm run lint:gate     # 闸门：只认官方审查规则，要求 0 条 error（已接进 tools/release.sh 第②步）
```

**只卡 `obsidianmd/*`，不卡 TS 噪音**：插件自带的 `recommended` 配置同时带进了
`@typescript-eslint` 的 `no-unsafe-*` / `no-explicit-any`，本仓库有 **326 条**这类告警
（大量来自 `plugin: any` 的既有写法）。它们**不是官方审核会拦的问题**，逐条修要动核心类型、
风险远大于收益——所以闸门按规则前缀过滤。

**`minAppVersion` 是这里的硬约束**：`obsidianmd/no-unsupported-api` 会拿 `manifest.json` 的
`minAppVersion` 去比对 API 的 `@since`，**对不上就是 error**。2026-10-16 为了清掉一批废弃 API
警告，把 `minAppVersion` 从 **1.4.0 抬到 1.13.0**（1.0.3 起生效）：

| 换成的新 API | 需要 | 为什么换 |
| --- | --- | --- |
| `FileManager.trashFile()` | ≥1.6.6 | `Vault.delete()/trash()` **无视用户「删除到回收站」的设置**，是永久删除 |
| `setDestructive()` | ≥1.13.0 | `setWarning()` 弃用 |
| 去掉 `setDynamicTooltip()` | ≥1.13.0 | 官方说明「值现在总是内联显示」，该方法弃用 |
| `createSpan/createDiv/createEl/createSvg` | — | 官方要求别用 `document.createElement` |

**已知并接受的 2 条 warning**（不阻塞发布，改起来要动大块代码）：

1. `@typescript-eslint/no-deprecated` —— `main.ts` 的 `settingTab.display()`：
   用来在设置变更后刷新设置页。**官方没有提供公开的替代**（指引里的
   `getSettingDefinitions()` 是另一套声明式 API）。要清掉它得整体改设置页，见下条。
2. `obsidianmd/settings-tab/prefer-setting-definitions` —— 设置页没有实现
   `getSettingDefinitions()`，所以 **1.13+ 用户在设置搜索里搜不到本插件的设置项**
   （设置页本身工作正常）。这是**真正待办**：设置页现有约 600 行手写 `new Setting(...)`，
   迁到声明式 API 是独立一轮活。

> ⚠️ **绝对不要用 `eslint --fix` 一把梭**：实测它的自动修复会把 `any` 改成 `unknown`、
> 把类型断言改坏，跑完 `npm run check` 直接报错（本仓库 `tsconfig` 是 `strict`）。
> 要修就逐条改，每改一批跑一次 `npm run check`。
>
> ⚠️ 规则的 `ignoreRegex` 用**JS 正则**，不支持 `(?i)` 内联标志——写错会让 eslint 整个崩
> （`SyntaxError: Invalid group`）。要放行专有名词用 `ignoreWords`（见 `eslint.config.mjs`
> 里放行「Agent」的那条）。

    > **相关设计约定**：凡是「操作某一项」的方法，都要显式带上它属于谁，别让它去猜全局状态（已修案例见 §5.1 A19）。
