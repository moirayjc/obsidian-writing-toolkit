## 1. 这是什么，长什么样

一个 Obsidian 中文网文写作插件（`id: writing-toolkit`，非桌面专属，手机端可用）。约 **16,700 行 TypeScript / 34 个模块**（实测 16,724 行），外加 6,986 行 CSS。

### 1.1 它长在磁盘上的哪里 ⚠️ 先看这条

```
<你的库>/.obsidian/plugins/writing-toolkit/     ← 仓库根 = Obsidian 实际加载的插件目录
├── src/            34 个 .ts（git 跟踪，实测 16,724 行）
├── styles.css      6,986 行（git 跟踪）
├── docs/           本文件所在（**尚未纳入 git**，见 §7）
├── main.js         ← 构建产物，**git 忽略**，但 Obsidian 加载的就是它
├── manifest.json   版本号（git 跟踪）
├── versions.json   版本 → minAppVersion 映射（git 跟踪）
├── data.json       ← 用户设置与统计数据，**git 忽略**
└── _backup/        历史快照，8.3 MB，**git 忽略**
```

> 本文所有相对路径都以这个目录为根（例如 `src/main.ts` = `<你的库>/.obsidian/plugins/writing-toolkit/src/main.ts`）。

**这是一处「原地构建」**：`npm run build` 直接把 `main.js` 与 `styles.css` 写进 `src/` 的上一层——也就是**正在被 Obsidian 加载的那份插件**。所以：

- 改了源码**必须重新构建**才生效（`main.js` 不会自己更新）；
- 构建**没有暂存区**，构建烂了当场就是可用性故障；
- 唯一的安全网是构建前的 `_backup/` 快照（见 §6.3）。

### 1.2 技术栈与硬事实

| 项目 | 事实 |
| --- | --- |
| 语言/构建 | TypeScript 5.3 + esbuild 0.20（`esbuild.config.mjs`），CommonJS、target ES2020、`strict: true` |
| 依赖 | 全部 vendored 在 `node_modules/`（含 esbuild、typescript），**可离线构建** |
| 类型检查 | `node_modules/.bin/tsc --noEmit` 当前**干净通过**（2026-10-16 核验） |
| 测试 | **没有任何测试框架**（无 vitest/jest、无 test 目录、无 test 脚本） |
| Lint | **没有 eslint 配置** |
| 验证方式 | 只有「构建 + 在 Obsidian 里实际点一遍」+ 一条自检命令（见 §4.6） |
| 官方审核 | 已通过并发布到社区插件中心，当前 1.0.2 |

> **这条最影响你的工作方式**：没有自动化测试，也没有本地跑起来的 Obsidian 可供断言。**任何改动都以「能被人在 Obsidian 里肉眼确认」为验收标准**，别指望 CI 帮你挡。改动前先构建一次留一份能回退的 `main.js`。

## 2. 数据与存储模型

### 2.1 一处落盘

| 数据 | 位置 | 命名/键规则 | 谁负责 |
| --- | --- | --- | --- |
| 插件设置（38 键） | `data.json → settings` | 见 §4.8「当前全部设置项」 | `settings.ts` |
| 今日净增 / 毛新增 / 有效时长 | `data.json → dailyHistory / dailyGrossHistory / dailyDurationHistory` | 键 `YYYY-MM-DD` | `main.ts` |

| 每文件字数基线 | `→ fileBaselines` + `baselinesAt` | 键 = 文件路径 | `statusbar.ts` + `main.ts` |
| 番茄记录 | `→ dailyPomodoroHistory` | 键 `YYYY-MM-DD`，值 `{count, words}` | 字段与读写都在 `main.ts`（`130`、`763-780`）；`pomodoro.ts` 只管计时器 |

> `data.json` 属于**用户数据**，已 gitignore。改数据格式时必须写迁移，不能直接改字段名（见 §4 禁忌 6）。

### 2.2 伴随文件（sidecar）——本插件的核心设计

**原则：正文一个字都不动。** 所有「跟着文档走」的数据都写到同目录的伴随文件或隐藏目录：

| 数据 | 路径规则 | 格式 | 模块 |
| --- | --- | --- | --- |
| 批注 | `正文/第1章.md` → `正文/第1章.批注.md` | 带 Agent 协议的 Markdown（见下） | `comments.ts` |
| 章纲 | `.wt-outlines/<正文相对路径>`（**连 `.md` 一起镜像**） | 章纲纯文本 | `outlineText.ts` |
| 草稿快照 | `.wt-snapshots/<正文相对路径>/<正文名>-20260826-172407413.md` | 整份 Markdown 副本 | `snapshot.ts` |

**作品的目录结构本身不持久化**，每次实时扫描（`project.ts:192-293`）。

路径写法要分清两种：**隐藏目录（`.wt-*`）用 `adapter` 直读直写**，**普通路径用 `vault` API**（章纲 `outlineText.ts:254-280` 是前者）。需要用 YAML frontmatter 时**只用 `vault.process` 行级替换**并留开关，不要整文件重写。

关键工具函数（`comments.ts`）：`sidecarPathFor` / `docPathForSidecar` / `isSidecarPath` / `isCommentSidecarName`。`isInternalPath`（`project.ts:81`）把**任意路径段以 `.` 开头**（`.obsidian`、`.trash`、`.wt-*`）的路径视为内部路径，一律排除出「正文」。

**批注文件的结构与 Agent 协议**（协议抬头逐字引用 `comments.ts:507-517` 的 `SIDECAR_HELP_HEADER`，序列化 `serializeCommentFile:533`，解析 `parseCommentFile:605`）：

```markdown
<!-- 写作工具箱 · 批注文件
这是作者写给「负责修改本文档的 Agent」的批注。

给 Agent 的处理方式：
1. 逐条阅读下方批注，对照每条里的「原文」在源文档中找到对应位置，按「批注」的要求修改源文档；
2. 每条处理完后，只修改该条批注的这些地方——「状态」改为：已处理；在「回复」后写明你做了什么改动（回复多于一行时，从第二行起每行都缩进两格，例如：- 回复：第一点\n  第二点）；
3. 如果你改写了「原文」对应的文字（哪怕只是挪了位置），就把改完后该处现在的文字照抄进「现文」（新增一行：- 现文：……，不要加引号、不要换行）；如果原文一个字都没动，可以不写；
4. 其余文字（包括本说明）请勿改动，也不要删除批注条目。
-->

# 批注 · 第1章

### 批注 1
- 状态：待处理
- 原文：……
- 段落：……            ← 建批注时所在整段
- 现文：……            ← Agent 改稿后写回（没改写就不用写这一行）
- 位置：第 3 段 · 约第 12 行
- 创建：2026-08-26 17:24
- 内容：……            ← 作者的批注
- 回复：……            ← Agent 写它改了什么
```

> ⚠️ **抬头原文以 `comments.ts:507-517` 为准**：改协议时改代码里的常量，不要只改这份文档。字段行是可选的——`段落` / `现文` 为空时**不输出该行**（看上面的 `writeField` 条件），所以真实文件不一定有全部 8 个字段。

- 解析**刻意容错**：字段顺序任意、列表符号 `- * +` 都认、未知字段忽略、多行值用**两格缩进续行**（`writeField:523` / `stripIndent`）。**历史上解析器太挑格式会造成「整条批注静默消失」并连带后续保存永久丢失**（见 §5.1 A12），所以宽容是硬要求。
- 状态认不出来时**一律当「待处理」**——宁可多看一眼也不漏（`parseStatus` 注释原文）。
- 批注 id 文件内唯一、**删除后不重排**，新批注取 `max + 1`（`nextCommentId:106`）。
- **库内有真实样例可对照**：`*.批注.md` 已存在于库中（当前 1 个文件），改解析器前后都可以拿它做回归验证。**docs/ 里不要贴它的内容**（正文与批注都是个人创作内容）。

### 2.3 「作品」识别：一切统计与权限的地基

`project.ts:19-27` 的注释用**结构识别**把目录树聚合成 `作品 → 卷 → 章`，支持三种组织方式：

- **A. 正文草稿目录**：`P3-某某/P3.3-正文草稿/第1章.md` → 作品 = 草稿目录的上一级，卷 = 草稿目录本身；
- **B. 按卷分目录**：`《书名》/第1卷·某某/第10章 某某.md` → 作品 = `《书名》`，卷 = `第1卷·某某`；
- **C. 章节直接放在目录里**：`《书名》/第1章.md` → 该目录自身即作品。

> 📌 上面这些示例是**脱敏改写过的**。原始注释里写的是**真实作品名与角色名**（见 §7 第 3 条），**改动到 `project.ts` / `main.ts` 这些注释时顺手换掉**，别再把自己或别人的真实作品名写进公开仓库。

识别结果由 `main.ts` 缓存为 `projectIndex()`（作品列表）+ `chapterPaths()`（章节路径集合，判定 O(1)）。库结构变化时 `invalidateProjectIndex()` 失效重建。

> ⚠️ **「算不算正文」= `chapterPaths().has(path)`**，不是路径关键词匹配。旧实现按「路径里有没有『正文草稿』四个字」判断，结果把 `.wt-outlines` 下镜像的章纲也算进正文、又漏掉按「第N卷」分目录的存档长篇——这条是**已记录的历史坑**（`main.ts:1481-1487`）。**任何新功能想判断「这是不是正文」，都必须用 `isDailyCountFile()` / `chapterPaths()`，不要自己写字符串匹配。**

### 2.4 快照

- 触发：`DraftSnapshotManager.tick()` 每 30 秒被 `setInterval` 调一次（`main.ts:253-256`），按 `snapshotIntervalMinutes`（间隔）与 `snapshotIdleMinutes`（空闲）判定；**内容没变就跳过快照**（`snapshot.ts:63` 注释）。
- 命名：`原名-YYYYMMDD-HHMMSSmmm.md`（`timestamp:491`），按源文件目录镜像到快照目录下。
- 清理：每文件最多 `snapshotMaxPerFile`（默认 20）份，超出删最旧（`snapshot.ts:415`）。
- 对比/恢复：`snapshotDiff.ts`；恢复走「程序化编辑」通道（见 §3.4），并且**会临时关掉海明威模式再恢复**（`snapshotDiff.ts:341-350`）。

### 2.5 字数统计

`wordcount.ts`，先剥两层再数：

```
原始文本 → stripFrontmatter（YAML，必须首行 --- 且闭合行也在行首）
        → stripInlineFormatting（HTML 标签 + 成对格式记号）
        → 三种模式之一
```

| 模式 | 内部名 | 规则 |
| --- | --- | --- |
| 番茄模式（含标点） | `webnovel` | 所有非空白字符，标点计入（**默认**） |
| 标准模式 | `standard` | 汉字 + 字母 + 数字 |
| 原生模式 | `native` | 汉字逐字 + 非 CJK 按 `\p{L}\p{N}+` 分词 |

> **格式记号必须剥掉**：编辑工具条写入的 `**` `==` `~~` 是**真实文档文本**，不剥就会虚增字数（`**粗体**` 在番茄模式多算 4 字）。剥离逻辑在 `formatWrap.ts:329-335`；斜体剥离**刻意要求星号后紧跟非空白非星号**，以免误剥作者手写的 `* * *` 场景分隔线与 `* 列表项`（`formatWrap.ts:320-322`）。**新增任何写入正文的记号语法，必须同步更新 `stripInlineFormatting`。**

## 3. 关键机制（改功能前必读）

### 3.1 主插件类的状态

`main.ts` 的 `WritingToolkitPlugin` 是一个**有大量字段的单体类**，字段分四类：设置/统计历史、界面记忆、缓存（`projectIndexCache`、`chapterPathCache`）、运行时句柄（`statusBar`、`snapshotManager`、`pomodoro`、`commentStore`）。

它还 `implements CommentPanelHost`（`main.ts:117`），给侧栏批注面板当宿主。

**热更新靠「签名比对」**，不用 Obsidian 的 `Compartment`：设置变了就比对上一次的签名字符串（`lastFormatToolbarSig`、`lastCommentsEnabled`、`lastDraftKeywords`、`lastChapterExcludeNames`），不一致才做重建或 `workspace.updateOptions()`。这些判断集中在 `saveSettings()`（`main.ts:2710-2745`）。**新增一个需要热生效的开关，就照这个模式加一个 `lastXxxSig` 字段，并在 `saveSettings()` 里补上比对。**

### 3.2 编辑器扩展（CodeMirror 6）

**全仓没有 `Compartment`、没有 `EditorView.theme`；样式全在 `styles.css`。** 6 个扩展全部经 `registerEditorExtension` 注册（`main.ts:277-301`），热更新统一靠「模块级开关变量 + `app.workspace.updateOptions()`」。

| 扩展 | 形态 | 装配点 | 开关 |
| --- | --- | --- | --- |
| 格式工具条 | `ViewPlugin.fromClass` + 诊断探针 `EditorView.updateListener` | `main.ts:282-290` | `formatToolbarEnabled` + `formatToolbarScope`（签名 `lastFormatToolbarSig`） |
| 批注痕迹 | **`StateField<DecorationSet>`** + 不产装饰的 loader `ViewPlugin` + `domEventHandlers` | `main.ts:293-301` | `commentsEnabled`（变化 → `refreshAllCommentDecors()`） |
| 打字机 + 段落高亮 | 3 个 `ViewPlugin`（段落高亮插件带 `decorations` facet / 底部留白 / rAF 滚动） | `main.ts:277` | 模块级 `typewriterActive` 等 |
| 标点辅助 | `EditorView.inputHandler.of` | `main.ts:278` | 模块级 `punctuationAssistActive` |
| 回车即新段落 | `Prec.highest(keymap.of([{key:"Enter"}]))` | `main.ts:279` | 模块级变量（run 内每次读，**不需要** `updateOptions`） |

**扩展不读 settings**：一律由 `main.ts` 通过 config 回调注入（`isEnabled()`、`allowsPath(path)`、`commentsEnabled()`、`getComments(path)`…）。保持这个约定，扩展才能保持可测试、可热切换。

#### 格式工具条

- **触发**：选区浮出（`ViewPlugin.update()` → `scheduleRefresh()`）；或命令面板 6 条 `格式：…` 命令。两者最终都进 `applyFormatOnView`。
- **定位**：锚在 `state.selection.main.head`，先加 `is-visible` 量尺寸，默认在下方 8px，下方放不下且上方够则翻到上方，四周夹 8px 边距。
- **必须在 `view.requestMeasure({read})` 里读坐标**——CM6 更新期间读布局会抛 `Reading the editor layout isn't allowed during an update`。
- **气泡挂在 `document.body`**，CSS `position: fixed; z-index: var(--layer-popover)`，且**刻意不进 `.wt-*` 主题作用域、直接用 Obsidian 原生变量**，以便在任何主题下跟系统气泡一致。
- **手机端三件套**：点按钮会让编辑器失焦 → 用 `interacting` 标志 + document `pointerup` 捕获监听，失焦期间不收起；`mousedown` 一律 `preventDefault` 防止选区被抢。
- **显示判定的顺序就是代码顺序**（`formatToolbar.ts:292-331`）：`composing` → 非 Markdown 编辑器 → 范围判定（格式与批注**分别**判定，批注可「全库浮出」）→ 选区全空 → 无焦点且非点按气泡中 → `coordsAtPos` 为 `null`。**每条隐藏路径都先记原因再隐藏并计数**（诊断数据 `formatToolbarDiag`），排查时看计数就知道卡在哪一步。
- **只在真 Markdown 编辑器里生效**：用 `state.field(editorInfoField, false)` 判存在（`formatToolbar.ts:246-249`）——搜索框等其它 CM6 实例必须排除。
- **范围三档** `formatToolbarScope`：`all` / `all-except-chapters`（默认）/ `library-only`，判定在 `main.ts:1500-1511` 的 `formatToolbarAllowed`。
- **包裹与还原**在 `formatWrap.ts`，是**不 import 任何东西的纯函数**（便于单测），返回 `{changes, selFrom, selTo}`。要点：选区要**留在正文文字上**（方便连加多种格式）；单星斜体只认**奇数层**，双字符记号够层数即可；字色用固定 `<span style="color: #hex">`，识别开始标签只回看选区前 96 字符。

#### 批注的渲染（改批注前必读）

**形态**：`StateField<DecorationSet>`，理由写在 `commentDecor.ts:7-10`——**块级装饰不允许来自 ViewPlugin（CM6 会抛 RangeError）**，且状态字段保证装饰在视口计算前已确定。

**两样痕迹**：
1. **原文底色标记** `Decoration.mark`（`class="wt-comment-mark"` + `data-wt-cid` + `title`）。**只有 `via !== "paragraph"` 才画**——定位退到「整段」时原文已大改，画底色会把整段涂掉。
2. **行尾脚注序号** `Decoration.widget(side: 1)`，`span.wt-cnote`，`textContent = 批注 id`；段落定位时落在该段末尾。它的 `eq()` **必须覆盖 `toDOM()` 用到的每个字段**（`id`/`status`/`via`/`content`/`reply`）——漏了就会复用旧 DOM，tooltip 一直显示旧文字（这是修过的 A17）。

**点击跳转的四个条件**（`commentDecor.ts:238-254`）——为的是**避免拖动选择被批注的文字时误跳侧栏**：同一个 cid、位移 `|dx|+|dy| ≤ 4`、间隔 ≤ 600ms、能在缓存里找到该 id。

**`dispatchCommentRefresh` 是唯一的外部数据 → 装饰重建入口**（`commentDecor.ts:52-64`）：
- `view.composing` 时**400ms 后重试**——拼字期间 dispatch 会打断拼音输入；
- try/catch 吞掉「视图已销毁」；
- 数据变化**不会**自动重建装饰，必须显式调它。

**为什么编辑器里一个浮层都没有**：跟随光标的卡片会随正文滚动而「跳」，看着累（`main.ts:291-292`、`1621-1626`）。所以正文里只有标记 + 脚注号；列表、编辑、删除、标记已处理全在**工具箱侧栏的「批注」标签**；写批注/改批注用**屏幕居中**的输入框（`CommentDraftModal`）。

> 这条经历过三轮返工才定下来：先做「跟随选区浮层」→ 用户反馈*「会让编辑器内的批注卡片也跟着跳来跳去，看上去并不舒服」*→ 尝试原地更新同一个 DOM → 用户仍是*「还是会跳，不如不要编辑器内的卡片，只保留侧栏的卡片」*→ **最终把 `commentPopover.ts` 整个删掉**。**不要在编辑器里再加任何跟随文字的浮层。**

**跳转链路**：点标记/脚注号 → `onRevealComment` → `revealCommentInPanel`（`main.ts:1899-1918`）→ `openSidebar()` → `sidebar.revealCommentCard`（`sidebar.ts:528`）→ `CommentPanelBody.revealCard`（`commentView.ts:101-126`，先放开「只看待处理」与已处理折叠 → 重渲染 → `scrollIntoView({block:"nearest"})` → `is-revealed` 闪一下）。

**侧栏整段的设计要点（改它会连锁坏掉）**：

- **侧栏 DOM 刚 `setViewState` 时还没建好** → `reveal` 立即失败要在 **120ms 后重试**（`main.ts:1907-1912`）。
- **面板用「内容签名」跳过重绘**，否则会出现「要点两次才跳」；异步渲染带**代数 `renderSeq`** 丢弃晚到的结果；重建后**还原滚动位置**（`commentView.ts:73-80`、`158-171`、`295-299`）。
- **跳转前必须放开筛选/折叠**，否则卡片在「只看待处理」或已处理折叠组里等于不存在（`commentView.ts:101-112`）。
- ⚠️ **已知缺陷**：`revealCommentInPanel` 里 `void path`（`main.ts:1917`）**没有用上这个 path**，面板数据取的是**活动文档**（`getCommentPanelModel` 用 `activeCommentDocPath()`）。所以在**后台编辑器**（不是当前活动文档）里点批注标记，`revealCard` 找不到卡片会**静默返回**。这是 §7 待办之一。


**锚点定位五层**（`comments.ts`，装饰 / 面板 / 跳转共用同一实现）：

| 顺序 | `LocateVia` | 界面文案 |
| --- | --- | --- |
| 1 | `present` | 按现文定位 |
| 2 | `exact` / `fuzzy` | 精确命中 / 已自动重新定位（忽略空白差异） |
| 3 | `residue` | 原文已改写，按上下文定位（段内残余：取原文前后的文字各 ≤28 字来夹；**头、尾都不到 4 字就放弃**；尾部须在起点后 600 字内） |
| 4 | `paragraph` | 原文已改写，定位到这一段（整段紧凑匹配；否则相似度 ≥0.55；候选段长 ≥6 字；同分按 `paragraphHint` 就近） |

### 3.4 字数统计的完整链路（最容易改错的地方）

```
                            ┌─ 编辑器输入 ──────────────────────────────┐
                            │ handleEditorChange                        │
                            │  · 程序化编辑（快照恢复/应用格式）→ 只重设基线，不计入
                            │  · 外部同步刷新（AI 改完 Obsidian 刷新编辑器）→ 已由 vault 路径统计过
                            │  · 新文件第一笔内容 → 整份算新增
                            └───────────────┬───────────────────────────┘
外部 AI/脚本直接改文件 ──► handleVaultModify ─┤
  （只触发 vault modify）   · externalModifyQueue 串行化，防异步竞态
                            ▼
                    applyDailyStats(file, delta, 计不计时长)
                            ▼
        dailyTotal / dailyGross / dailyDurationHistory / fileBaselines
                    ▼
                状态栏 + 侧栏 + 主页热力图
```

**必须记住的规则**：

1. **净增 vs 毛新增**：`dailyHistory` 是净增（可正可负），`dailyGrossHistory` 只累加变多的部分且永不为负。今日目标与热力图用**毛新增**，避免「重写一整天显示 0 或负数」（`main.ts:120` 注释）。
2. **外部修改必须串行**：AI 连续多次写入时若并发读盘会漏计或让基线倒退，所以走 `externalModifyQueue` 队列（`main.ts:186`、`1306`）。
3. **「写作时长」有 30 秒的空闲上限**：两次输入间隔超过 `MAX_IDLE_GAP_MS = 30_000` 即视为停止写作，这段间隔**不计入时长**（`main.ts:104-106` 注释：2026-08-13 由 120s 收紧为 30s，「避免停顿（喝水/切走/思考）被全额算作写作时间」）。**改时长统计别绕过这个阈值。**
4. **程序化编辑要按「编辑器 + 最终文本」精确匹配后忽略**（`pendingProgrammaticEdit`，`main.ts:1204`）；外部写入的内容要记下来供编辑器识别同步刷新（`lastExternalSyncText`）。
5. **切换统计模式必须先改模式再重建基线**，否则会拿「新模式计数 − 旧模式基线」得到巨大误差（`main.ts:794-819`）；番茄专注中也要同步重设番茄基线。

**基线档案**：`fileBaselines` 记录每个文件最近一次已知字数；`baselinesAt` 是「上次建立基线档案的时间戳」。启动时 `scanNewFilesOnLoad` 只对**上次退出后新建**的正文文件按整份内容计入当天，更早的文件只建档不追溯（`main.ts:1317` 起）。文件改名/移动要把基线一起搬（`main.ts:2461`），文件删除要清掉旧基线（`main.ts:614`）。

> **焦点无关原则**：侧栏/工具箱获得焦点时 `workspace.getActiveFile()` 会返回 `null`。所以快照、批注、统计都不能依赖「当前焦点」，而要用 `lastKnownPath` / `lastKnownText` / `currentMarkdownView()` 兜底（`main.ts:180-184`）。

> **读-改-写必须用 `vault.read`，不能用 `cachedRead`。** `cachedRead` 返回的是**可能过期的缓存内容**，用它做「读全文 → 改 → 写回」会把 Agent/其他工具刚写入的内容**覆盖掉**（这是踩过的坑）。`main.ts` 里现存的 4 处 `cachedRead`（`1306`/`1340` 周边统计、`1942` 复制干净正文、`2018` 定位锚点）**都只读不写回**，可以保留；但只要你的新代码打算**写回**，必须先 `vault.read` 拿最新内容。批注的读写路径（`commentStore.ts:58` 用 `vault.read`）遵守这条。

### 3.5 主题与配色的双层机制（改样式的核心约定）

> ⚠️ **先记这条会让人崩溃的坑：自定义属性必须挂在 `body` 上，不能挂 `:root`。**
> Obsidian 的 `--text-*` / `--background-*` 都定义在 `body`。如果你在 `:root` 里声明并引用它们（比如批注的 `--cmp-*` 令牌），`var()` **解析不到值 → 整条声明变成无效值 → 整条属性失效**。后果是「正文里的批注标记整片看不见，只剩一个孤零零的序号」。这个坑的结论就写在 `styles.css:5212-5214` 的注释里，**新增任何自定义属性令牌都请沿用 `body` 前缀**。

**令牌体系**：样式不直接用 Obsidian 变量画自己的界面，而是先定义一套 `--wt-*` 设计令牌（`--wt-paper`、`--wt-ink`、`--wt-accent`、`--wt-rule`、`--wt-card-bg`、`--wt-shadow`…），令牌值**按配色主题 × 明暗各给一套**，定义在选择器内：

```css
/* styles.css 片段（暖纸默认值写在 .theme-dark .wt-wb, .wt-sidebar, .wt-settings-page 等） */
.theme-dark .wt-wb, .theme-dark .wt-sidebar, .theme-dark .wt-settings-page {
  --wt-paper: #1d1a17;  --wt-ink: #ece4d6;  --wt-accent: #e07a5f;  ...
}
/* 换配色：body 上挂类，令牌整体换掉 */
body.wt-theme-cool      :is(.wt-home, .wt-wb, .wt-sidebar, .wt-settings-page) { ... }
body.wt-theme-cool.theme-dark :is(...)                                       { ... }
body.wt-theme-contrast  :is(...)                                             { ... }
```

组件样式只消费 `var(--wt-*)`；`styles.css` 中 `var(--wt-ink-)`/`var(--wt-accent*)`/`var(--wt-ink)` 等令牌被引用数百次。**新增界面元素 = 消费已有令牌，不要在组件里写死颜色。**

**首帧不闪（这个机制很绕，别拆）**：Obsidian 在**插件 JS 运行之前**就加载已启用的 CSS 片段，所以插件把当前配色的令牌写进 `.obsidian/snippets/wt-theme-tone.css` 并同步启用状态（`syncThemeSnippet`，`themeSnippet.ts:101-118`）：

- 暖纸（默认）→ 片段停用（内容只有一行注释）；
- 冷调 / 高对比 → 片段启用，且**给所有变量与 `background` 声明统一加 `!important`**，以压过 `styles.css` 里的暖色规则（含暗色下优先级更高的渐变背景），**不依赖选择器特异性**；
- 片段选择器**不能依赖 `body.wt-theme-*` 类**（那个类要等 JS 才加上），所以用 `body` 前缀 + `:is(...)` 抬特异性；
- 双保险：`typography.ts:9-27` 还把配色缓存进 `localStorage["wt-theme-tone-cache"]`，`onload` 里 `applyCachedThemeTone()` **在第一个 `await` 之前同步执行**（`main.ts:199-200`），避免首帧闪成暖纸。
- 整个同步 try/catch 只 `console.warn`（`themeSnippet.ts:115-117`），失败降级为默认暖纸。

**排版注入**只用「CSS 变量 + body 类名」（`typography.ts`），**不动态创建 `<style>` 元素**——Obsidian 审核明确禁止（`typography.ts:29-30` 注释）。段首缩进是纯视觉 `text-indent: 2em`，不往正文写空格。

**⚠️ 追加式增长带来的三个结构性问题**（改样式前必须知道）：

1. **同一选择器被声明多次，后者覆盖前者**：按完整选择器统计，全文件有 **50 个选择器被声明 >1 次**（若把逗号分隔的选择器组和 `@media`/`@container` 内的一起拆开算，数量更多（约 77），口径不同不影响结论）。例如 `.wt-sidebar .wt-settings-tabs` 在 318 与 3453、`.wt-combo-menu` 在 428 与 3725、`.wt-sidebar-section` 在 365 与 3527、`.wt-snap-row` 在 554 与 613。**改一条规则前先搜一遍有没有同名规则在后面覆盖你。**
2. **末尾有一整块「从 1.0.1 恢复」的裸选择器兼容回填**（`styles.css:5736-5857`，注释写明「当前版本已改写为带父级前缀的选择器，这些裸选择器需保留」）。**别当成死代码删掉**——删了 `1.0.1` 时代的样式会丢（这正是那次大回滚的遗留）。
3. **有被压成单行、与前面重复的规则**（如 `5694` 行的 `.theme-dark` 令牌与 `1412-1430` 的完整版重复）。

**`!important` 共 77 处**，分布很不均：主页+侧栏+设置页区间占约 **57 处**，手机版区间（`4489-4814`）**8 处**（其中真正的 `body.wt-mobile` 规则内只有 1 处 `padding-top`），其余零星。**注释里唯一解释了理由的是 `styles.css:4802`**（压过 Obsidian 写在 `.cm-content` 上的内联 `padding-bottom`）。另外两处合法理由是片段文件与按钮清除（见下）。**新的 `!important` 要写清理由**，并用「父级前缀提高特异性」替代它。

**必须清除的宿主默认样式**：Obsidian 主题给 `<button>` 的**冷灰底色压在暖纸上会「跳出来」**，且默认还带 `box-shadow`。所以新面板里的 `<button>`/`<input>`/`<select>` 记得三连清 `border: 0; background: transparent; box-shadow: none`（先例 `styles.css:4065-4071`，注释原文「主题给 button 的默认底色是冷灰，压在暖纸上会跳出来」；`5879-5882` 是 `.wt-wb button` 的 `font-family`/`box-shadow` 补充）。

**无障碍与触摸**：`@media (prefers-reduced-motion: reduce)` 3 处、`@media (hover: none)` 1 处（触屏让批注卡片操作常显）。新增动画要考虑 reduced-motion，新增「悬停才显示」的控件要补 `hover: none`。

### 3.7 ⚠️ 样式调试没有反馈回路（本插件最痛的工程约束）

这不是比喻，是历史事实：**CSS 坏掉的方式全是静默的**，而开发时**看不到 Obsidian 的渲染结果**，反馈回路长达「一整个用户往返」——曾经一轮合并改动连环引爆 8 个新问题（丢了 `background: transparent` 导致按钮露灰底、丢了 `border` 导致状态胶囊没边框、`--wt-wb-hair`/`--wt-wb-wash` 变量没定义、属性 diff 显示「0 处差异」但视觉不同），全靠用户来回截图描述才定位。

而且**自动比对 CSS 极不可靠**（历史上连续误判 4 次）：
- 把 `.wt-settings-tab` 重写为 `.wt-sidebar .wt-settings-tab`（提升特异性）会被文本比对误判成「选择器丢失」；
- **同名 `:is()` 块会完全覆盖**后者：新加的批注样式块遮蔽了 1.0.1 的 17 个暖纸变量，**属性级 diff 显示 0 处差异，但视觉全变**；
- 把「新版没有某声明」当成删除，就会误删 `background: transparent` 与 `border`。

**所以：**
1. **不要用脚本"合并/恢复"整个 `styles.css`**。历史上正是这类操作把状态栏、日历、热力图的样式一起覆盖掉的。**要么整文件用 git 恢复，要么手工最小改动。**
2. 比对两份 CSS 时，**必须做到「选择器 + 属性」级别的 diff**，并逐条判断是「删除」还是「移动/提高特异性」；文本级比对会骗你。
3. 复查视觉时**不能只看桌面中央编辑区**——**中央编辑区宽度变化本身就会让主页/欢迎页看起来"样式变了"**（曾据此误判整轮）。
4. **测看不到的面板**：批注面板历史上同时存在三个实例、其中两个是 `display: none`，测到的那一个 `width=0`，导致整轮排查方向错误。**测 UI 前先确认"你看的是哪一个实例、它是不是隐藏的"。**
5. 桌面调试移动端布局用命令「切换手机版布局预览（桌面调试）」，别只靠肉眼想象。

## 4. 开发规范与禁忌

### 4.1 红线禁忌（按事故严重度排序）

**禁忌 1 · 不要「顺手」大范围重写样式或界面代码。**
这是本插件**真实发生过的最严重事故**：某次改动把界面「改得面目全非」（主页左侧、欢迎页、按钮细节全变），最后只能从 git 1.0.1 回滚样式，再手工把新主题与批注功能合回去。**改样式只做外科手术式的最小改动**；要重构就先在 `_backup/` 留快照，并一次只动一块。另外注意：**中央编辑区宽度变化会让主页/欢迎页看起来"样式变了"**——先确认是不是布局宽度导致的错觉，再动 CSS。

**禁忌 2 · 不要把 `manifest.json` 的版本号随手抬到下一个大版本。**
社区插件发布必须保持 **`manifest.json` 的 `version` = git tag = `versions.json` 的键**，且三者同步。历史上曾把版本写成 `1.4.0`（应为 `1.0.2`），发布流程直接受阻——**根因是改错了字段：`1.4.0` 是 `manifest.json` 里的 `minAppVersion`，不是插件版本**。同一个文件里两个数字，改之前先看清字段名。`minAppVersion` 也要与 `versions.json` 一致。

**禁忌 3 · 不要把个人内容带进仓库。**
仓库公开在 GitHub。已 gitignore：`data.json`、`_backup/`、`main.js`、`*.map`、`.DS_Store`、`node_modules/`。**但仍有漏网**：源码注释里残留真实作品名——`main.ts:2805`、`main.ts:2840`、`project.ts:19-27`（真实作品目录名与角色名被当作识别规则与相似度匹配的示例）。改到这些文件时顺手**脱敏成虚构示例**，新增注释同理。发布前跑一遍 §6.1 的自检。**另外注意：提交署名里的作者邮箱是公开的**（历史上已公开），如果介意就换一个公开邮箱。

**禁忌 4 · 不要在编辑器里放跟随文字滚动的浮层。**
批注浮层被用户明确否掉两轮：*「会让编辑器内的批注卡片也跟着跳来跳去，看上去并不舒服」*→*「还是会跳，不如不要编辑器内的卡片，只保留侧栏的卡片」*。正文里只留**非滚动的**痕迹（底色标记 + 行尾脚注号），交互一律挪到侧栏面板与屏幕居中模态框。**任何新的编辑器内 UI，先假设它会滚动抖动。**

**禁忌 5 · 不要给同一个危险操作叠两道确认。**
删除批注曾同时有「按钮二次确认」和「弹窗确认」，用户得连点三次（*「我发现点完删除后，再点确认，它还会出来一个弹窗，再让我确认一遍」*）。现在的约定：**按钮 `删除 → 确认`（3 秒窗口）+ 删除后 6 秒内可「撤销」**，不再有弹窗。新增破坏性操作请沿用「一次确认 + 可撤销」，别叠。

**禁忌 6 · 不要直接改 `data.json` 的字段名/结构。**
用户数据里已经有真实历史统计（当前这份 `data.json` 实测：**顶层 18 键**、`settings` 38 键、`dailyHistory` 34 天、`fileBaselines` 371 条、`dailyFileDeltas` 4 天；**只有 `dailyFileDeltas` 裁剪到 60 天**（`main.ts:2548-2552`），其余历史 map 无限增长）。读设置走**白名单合并**（只取 `DEFAULT_SETTINGS` 里存在的键，顺带清掉废弃字段如 `fontSize`），统计字段用 `|| {}` 兜底。删/改字段必须写迁移，并在注释里写明旧格式保留策略（参考 `main.ts:2598`「老格式如有历史数据则保留，不主动清空」）。

> ⚠️ **这一块已经埋着一个真 bug，但只在旧扁平格式分支里**：`main.ts:2559` 与 `2581-2596` 共 **17 个字段**写成了 `DEFAULT_SETTINGS.xxx`（少了 `data.xxx ??` 前缀）。**正常的新格式用户走的是白名单合并分支（`2616-2623`），不受影响**——所以修的时候认准分支，别改错地方。详见 §7 第 10 条。**新增设置项时照 `2560-2580` 行的正确写法**，别复制粘贴错的那一半。

**禁忌 7 · 不要在 `onunload` 之外留下计时器、监听器与 body 元素。**
已注册的必须清：番茄钟定时器（`main.ts:657` 注释「避免插件禁用/重载后旧定时器继续 tick」）、快照 30 秒 tick、跨天检查定时器、`immersiveHintEl`、`injectTypography`（→ `removeTypography`，`main.ts:660`）、侧栏的 combo 菜单监听（`sidebar.ts` 的 `comboCleanups`）。**body 级监听一律用 `registerDomEvent`**，不要用裸 `addEventListener`。

**禁忌 8 · 侧栏/视图对象的方法要先判类型再调。**
踩过 `refreshComments is not a function`：侧栏 leaf 里的视图实例不一定是目标类，**必须逐项检查 `typeof x === "function"`**，否则一个可选方法的缺失会连带把「保存批注」这种无关操作一起弄失败（`main.ts:1563-1577`）。

**禁忌 9 · 原型类的 `display()` 可能被调多次。**
Obsidian 的 `ItemView.display()` 在视图重新显示时会被再次调用。**所有事件注册、资源创建都要幂等**（在 `display()` 里挂监听必须配对应的解除，或改用 `registerEvent`），否则会叠加监听与 UI。

**禁忌 10 · 不要把 `tsc --noEmit` 跑不过的代码构建上线。**
本项目 `strict: true` 且当前干净。构建前跑一次类型检查；构建产物直接落到正在运行的插件目录（§1.1），构建出坏代码 = 插件当场坏。

### 4.2 必须遵守的约定

1. **输入法优先**：`composing` 期间不弹浮层、不 dispatch、不拦按键。**遵守这条的是**：工具条（`formatToolbar.ts:295`）、批注刷新（`commentDecor.ts:54`）、回车硬换行（`hardBreak.ts:39`）。**海明威模式是例外且相反**：它没有 composing 守卫，`transactionFilter` 反而要在 `input.compose` 时**放行**（`hemingway.ts:39-44`）——否则中文组词会被拦掉。
2. **判断「正文」一律用 `isDailyCountFile()` / `chapterPaths()`**，不要写路径关键词匹配。
3. **判断「内部路径」用 `isInternalPath()`**（任一路径段以 `.` 开头）。
4. **正文文本绝不被功能副作用改写**（批注/章纲/快照都在伴随文件里）。唯一例外是用户主动的格式命令；章纲在 `frontmatter` 模式下才会写 YAML（`outlineText.ts:260-263`、`364-397`）。
5. **伴随数据是「路径派生」绑定**：正文改名/移动**必须**同步迁移伴随文件（批注、章纲、快照、基线、以及 `data.json` 里以作品根目录为键的统计与封面），漏一个就出现「脱钩」。
6. **章节连号重编号 = 多文件改名事务**：只收集严格连号的尾部；**认不出的写法或撞名就整体取消、不动任何文件**（`workbench.ts:2045-2087`）；删除后连号章节整体前移、**断号即停**；整卷删除要用 `deletingVolumePaths` 抑制逐章重编号（`workbench.ts:249-252`、`1244-1252`）；重编号要**保留原写法与补零宽度**。新功能涉及批量改名时照这个事务模型做。
7. **装饰层不写文档**：批注标记/脚注号是 CodeMirror 装饰的产物、**不在文档文本里**，所以「一键复制干净正文」天然干净；若你的功能确实要往正文写记号（如 `**`），必须同步更新 `stripInlineFormatting`，否则字数统计虚增（`formatWrap.ts:329-335`、`wordcount.ts:56-58`）。
8. **焦点无关**：不要用 `getActiveFile()` 当作唯一来源，用 `lastKnownPath` / `currentMarkdownView()` 兜底。
9. **扩展不读 settings**：由 `main.ts` 注入回调；热更新用「签名比对 + `updateOptions()`」。
10. **装饰重建必须显式触发**（`dispatchCommentRefresh`），并容错 `composing` 与已销毁视图。
11. **CSS 写在 `styles.css`**，用 `wt-` 前缀 + `--wt-*` 令牌；不动态建 `<style>`；自定义属性挂在 `body` 而非 `:root`（见 §3.5）。
12. **颜色/间距跟随令牌与主题**，不硬编码（现有硬编码色残留是历史债，别扩散）。
13. **数据变化后同步刷新界面**：`refreshSidebar()` / `refreshNow()` / 面板 `refresh()`；侧栏面板有「内容签名跳过重绘」与「`renderSeq` 代数丢弃晚到结果」两个防抖机制，照用。
14. **危险操作给结果反馈**：`Notice` 提示 + 可撤销窗口。
15. **别动用户的剪贴板**：调试「一键复制」这类功能时，**先读回确认再写**——历史上开发过程覆盖过用户正在用的剪贴板内容。

### 4.3 新增一类「跟随文档的伴随数据」

照 **`comments.ts` + `commentStore.ts`** 的模子写，必须实现：

| 必须项 | 说明 |
| --- | --- |
| `pathFor(docPath)` / `docPathForSidecar(path)` | 正反向路径换算；反向必须能识别「自己不是正文」 |
| `isXxxSidecar(path)` | 让 `isInternalPath`/作品识别/章节列表排除它（否则会被当成章节、计入字数） |
| `serialize()` / `parse()` | 纯函数、容错解析（字段顺序任意、缩进续行、未知字段忽略） |
| 缓存 + 失效 | `commentStore` 按源文档路径缓存；文件外部改动要失效 |
| 改名/移动跟随 | 源文档 renamed 时把伴随文件一起搬，**不覆盖目标位置已存在的文件**（`main.ts:2090`）；章纲同理会「脱钩」（`main.ts:602-603` 注释） |
| 删除源文档时的清理策略 | 明确跟删还是保留 |

再补两条容易漏的：

- **把「伴随文件」接进排除体系**：新后缀必须在**每一处**会被问到「这算不算章节/正文」的地方生效，漏一处它就会出现在章节列表或字数统计里。`.批注.md` 的防线按用途分两类，照这份清单核对自己的类型：
  - **靠文件名排除的**（普通目录里的 `.批注.md` 走这条）：`outlineText.ts:26-39` 的 `isExcludedChapterName` **内置豁免** → 默认「不算章节」名单 → `project.ts:111-119`（跳过）→ `outlineText.ts:134-146` → `snapshot.ts:34`。
  - **靠路径/上下文排除的**（隐藏目录、内部路径）：`main.ts:1488-1491` 的 `isInternalPath`/`isDailyCountFile` → `commentDecor.ts:137`、`210`（`isSidecarPath` 判断）→ `main.ts:463`、`1633`、`1930` → `workbench.ts:316` / `home.ts:294`。
  
  ⚠️ 注意：`workbench.ts:316` / `home.ts:294` 是 `isInternalPath` 守卫，**对普通目录里的 `.批注.md` 不起作用**——真正挡住它的是第一类里的内置豁免。**别只加内部路径守卫就以为够了。**
- **协议抬头与解析器必须同改**，而且协议里要写**多行缩进示例**（历史上两者脱节导致整条批注被静默丢弃）。另外两条**别乱动**的格式细节：
  - `# 批注 · <标题>` 这一行的**标题级别其实无所谓**——条目抬头正则 `HEADER_RE`（`comments.ts:567`）只在「批注」后**紧跟数字**时才匹配（实测 `## 批注 1` / `### 批注 1` 匹配，`# 批注 · 第1章` 与 `## 批注 · 第1章` 都不匹配），安全性来自中间的 ` · ` 分隔符而非 `#` 的个数。**真正要守住的是「别让标题行长得像条目抬头」**。
  - 字段值多行用**两格缩进续行**（`writeField:523`），解析时去缩进拼回；这是 Agent 手写回复时最容易写坏的地方，所以协议抬头里必须给例子。

### 4.4 新增一个面板 / 浮层

**第一步先决定「挂在哪」，这决定了你能不能直接用令牌**：

| 挂载位置 | 能不能用 `--wt-*` | 做法 |
| --- | --- | --- |
| 四个主容器内部（`.wt-home` / `.wt-wb` / `.wt-sidebar` / `.wt-settings-page`） | ✅ 能，**六套**配色（暖纸/冷淡/高对比 × 明暗）自动生效 | 直接消费令牌 |
| `document.body`（浮层 / 菜单 / 常驻条 / Toast） | ❌ **取不到页面令牌**（`styles.css:5022` 明写） | 二选一：① 像 `.wt-combo-menu` 那样在自身规则里定义 `--wt-menu-*` 并配 `.theme-dark` 覆盖；② 像 `.wt-mbar` 那样用 Obsidian 原生变量，**并按 `body.wt-theme-cool` / `body.wt-theme-contrast`（× `.theme-dark`）逐套补映射**（`styles.css:5021-5120`） |

**其余检查项**：

- **先判断它会不会滚动抖动**（禁忌 4）。会 → 放侧栏或居中模态框，不要跟文字。
- 挂侧栏：照 `sidebar.ts` 的标签页 + `wt-tb-card`；面板本体写成独立类（如 `CommentPanelBody`），带 `destroy()` 与内容签名。**只做一处，不要再注册独立视图**（历史上同一能力有两套实现）。
- 浮层挂 body + `position: fixed`：照 `formatToolbar.ts` 的三件套（`requestMeasure` 里读坐标、手机端 `interacting` + `pointerup` 捕获、`mousedown preventDefault`），`destroy()` 里移除 DOM 与 document 级监听。**`overflow:hidden` 的容器里不要放需要溢出的浮层**（会被裁剪），挂 body 或用 fixed 定位；滚动/缩放窗口时要自动关闭避免错位（`sidebar.ts:157-163`、`229-248`、`304-309`）。
- **命名**：一律 `wt-<域>-<部件>` + `is-*` 状态类，**不要用 `.panel` / `.card` / `.menu` / `.list` 这种泛化名**（会撞 Obsidian 原生与第三方主题）。
- **作用域**：所有选择器带 `.wt-` 或 `body.wt-*` 前缀；要压过原生控件用**父级前缀提高特异性**，别用 `!important`（反面教材：末尾那块「从 1.0.1 恢复」的裸选择器就是特异性收窄后不得不做兼容回填）。
- **清除宿主默认样式**：`<button>`/`<input>`/`<select>` 三连清 `border: 0; background: transparent; box-shadow: none`。
- **移动端**：布局差异写进 `body.wt-mobile` 段（**不要写 `@media (max-width: …)`**）；底部固定元素带 `env(safe-area-inset-bottom, 0px)`；触控目标 ≥44–46px；「悬停才显示」的控件用 `@media (hover: none)` 补常显；分支用 `isMobileUI()`（布局，含桌面预览）还是 `Platform.isMobile`（真机能力）要分清。面板若要进手机抽屉，走 `openInMobileDrawer` 并在 `migrateMobileViewsToDrawers` 里登记。
- **隐藏态**统一用 `.is-hidden` 类，不要内联 `style.display`。

### 4.5 新增一个编辑器功能

| 需求 | 照抄哪个模子 |
| --- | --- |
| 只是按选区改文本/切格式 | `formatWrap.ts` 写成**纯函数**（返回 `{changes, selFrom, selTo}`）→ 调用方用 `state.changeByRange` 套壳 → 同时接一条 `addCommand({editorCallback})` 走同一入口 + 范围校验 |
| 要在正文上画东西（标记/序号/高亮） | `commentDecor.ts`：`StateField<DecorationSet>` + `provide`，自定义 `StateEffect` + `dispatchXxxRefresh`（带 composing 重试与销毁容错），再加一个不产装饰的 loader `ViewPlugin` 处理异步预加载与初始化顺序 |
| 要浮出一个 UI | `formatToolbar.ts`（见 §4.4） |
| 拦按键 | `hardBreak.ts`（`Prec.highest` keymap）+ 跳过 composing / 代码块 / 空行 / 块级语法起始行 |
| 限制在某区域内编辑 | `hemingway.ts`（`transactionFilter` 拒绝非末尾改动 + 光标守卫）；注意「只进不退」的 StateEffect 语义 |

**初始化顺序的坑**：`StateField.create` 时 `editorInfoField` 可能还没就绪 → `readDocPath` 要 try/catch 返回 `null`（`commentDecor.ts:71-79`），再由 loader `ViewPlugin` 稍后补发一次刷新（`commentDecor.ts:197-215`）。

### 4.6 必要的可观测性：自检命令

排查「为什么没反应」不要靠猜。插件已有**一条**自检命令：

- **`格式：自检（排查工具条不出现）`**（`main.ts:408-414`）→ 收集每个环节的状态（`formatToolbarDiag`：视图更新次数、各隐藏原因计数…），报告写到库里 `0-收件箱/写作工具箱-自检报告.md`（否则库根）。实现：报告文本 `main.ts:2121` 附近，落盘 `writeDiagnosticReport`（`main.ts:2215-2240`，唯一调用点 `2117`）。

**新增容易「静默不生效」的功能时，照这个模式加一条自检命令**：把「为什么没生效」的每个分支都计数、落盘。工具条的诊断数据结构值得照抄——它把 `composing` / 非 Markdown / 范围外 / 无选区 / 无焦点 / 拿不到坐标这六条隐藏路径**各自计数**，所以一眼就能看出卡在哪一步。

### 4.9 怎么在没有测试框架的情况下验证逻辑（可复用的办法）

项目没有测试框架，但**纯逻辑/存储层可以用 Node 直接跑真实实现**，不必启动 Obsidian。2026-10-16 修 bug 时用的就是这套办法，两次都拿到了「修复前失败 / 修复后通过」的对照：

| 办法 | 适用 | 做法 |
| --- | --- | --- |
| **单独编译纯模块** | `comments.ts`、`formatWrap.ts`、`wordcount.ts`、`chapterOrder.ts` | `./node_modules/.bin/esbuild src/comments.ts --bundle --format=cjs --target=ES2020 --outfile=/tmp/x.js` —— 这些模块不 import Obsidian，编出来就能直接 `require` |
| **抽真实方法体跑** | `main.ts` 里的大方法（如 `loadPluginData`） | 按符号定位 + 花括号配平抽出方法体 → 用 esbuild 转译成 JS → 注入桩（`DEFAULT_SETTINGS`、`super.loadData()`）后用 `new Function` 执行。**逻辑一行不改**，所以结论可信 |
| **桩掉 `obsidian` 模块** | 依赖 `App`/`TFile` 的类（如 `CommentStore`） | 覆盖 `Module._load`，对 `require("obsidian")` 返回只含所需类型的桩；再用假的 `vault`（Map 实现 `getAbstractFileByPath`/`read`/`create`/`modify`/`delete`）驱动 |

**注意**：这些脚本验证的是**逻辑**，验证不了渲染、布局、主题、输入法——那部分只能进 Obsidian 手动点（见 §4.7）。另外**写断言时先确认自己模拟的事件序列与 Obsidian 一致**：我第一次测批注缓存时漏了 `create` 事件，误判成"修复没生效"——真实流程里插件是靠 `main.ts:560` 的 create 处理器失效缓存的。

### 5.2 已修复但仍易复发的坑（按技术面）

**坐标与滚动**

1. CM6 更新期间不许读布局，`coordsAtPos` 会抛异常 → 一律 `requestMeasure({read})` 延后（`formatToolbar.ts:224-239`）。
2. 气泡先加 `is-visible` 再量尺寸，否则量到 0；上下翻转 + 四边 8px 夹取。
3. 手机端点按钮会让编辑器失焦 → `interacting` + `pointerup` 捕获 + `mousedown preventDefault` 三件套。
4. 段落高亮会把标题/列表吸成一大段 → 独立 Markdown 块特判（`typewriter.ts:52-58`、`79-83`）。
5. 打字机底部留白压不过 Obsidian 写在 `.cm-content` 上的**内联** `padding-bottom` → 只能用 `!important`（`styles.css:4802`）。
6. 信纸横线用固定 px 会在标题字号变化后错位 → `background-size: 100% 1lh` + `background-origin/clip: content-box`。
7. 沉浸模式要隐藏左右栏/ribbon/tab/titlebar（`body.wt-immersive`），且**进入沉浸会临时强制打开打字机模式，退出必须还原**（`main.ts:821-836`）。

**CSS 层级与主题**

8. 工具条刻意放 `document.body`、**不进** `.wt-*` 主题作用域，用 Obsidian 原生变量——为了跟系统气泡一致。
9. 配色片段要压过插件自带暖色规则与暗色渐变 → 生成时统一注入 `!important`；片段选择器不能依赖 JS 才加的 body 类。
10. 首帧闪暖纸 → `localStorage` 同步缓存 + snippet 文件双保险。
11. Obsidian 审核禁止动态 `<style>` → 排版只能改 CSS 变量 + body 类名。
12. 选中色跟主题串味（高对比度下跳紫）→ 只覆盖 `.cm-editor` 的 `--text-selection`，不动全局设置。

**装饰与选区/撤销栈**

13. **块级装饰不能来自 `ViewPlugin`（会抛 `RangeError`），必须 `StateField`**（`commentDecor.ts:7-10`）。
14. 拼字期间 dispatch 会打断拼音 → `composing` 时 400ms 重试。
15. 状态字段 `create` 时 `editorInfoField` 可能未就绪 → try/catch + loader 稍后补刷新。
16. 拖动选择被批注的文字会误跳侧栏 → mousedown/mouseup 组合 + 位移 ≤4px + 600ms 窗口。
17. 数据变化不会自动重建装饰 → 必须显式 `dispatchCommentRefresh`。
18. 脚注号 widget 用 `side: 1`，`eq()` 要覆盖 `toDOM()` 用到的每个字段（`id`/`status`/`via`/`content`/`reply`），否则复用旧 DOM 会让 tooltip 停在旧内容（曾漏过 `content`，已修）。
19. 批注标记是**装饰层产物、不在文档文本里**，所以「一键复制干净正文」天然干净；脚注号还要 `user-select: none` 防止被一起选中。

**统计与数据**

20. 「算不算正文」别用路径关键词 → 用作品索引的章节集合（旧的会误纳 `.wt-outlines` 镜像章纲、漏掉按卷分目录的长篇）。
21. 切统计模式必须**先改模式再重建基线**，否则误差巨大。
22. 外部 AI 写入要串行排队，否则漏计/基线倒退。
23. 净增会为负，所以今日目标与热力图用**毛新增**。
24. `workspace.getActiveFile()` 在焦点位于侧栏时为 `null` → 一律用 `lastKnownPath` / `currentMarkdownView()` 兜底。
25. 侧栏刚 `setViewState` 时 DOM 还没建好 → `reveal` 立即失败要**延迟重试**（`main.ts:1907-1912`）。
26. 番茄专注中，外部字数变化要同步进番茄基线，否则 AI 的增删会被算进本番茄字数。

**输入法与按键**

27. 回车即新段落必须跳过：输入法拼字中、fenced code block 内、空行、块级语法起始行（`>` `-` `1.` `#` 表格 `|` 分隔线）。
28. 标点辅助的双右括号重复（`（内容））`）→ 输入闭合符时若右侧已是同一字符则只移动光标。
29. 海明威模式要允许「组词时替换末尾已有区间」（先插 `n` 再把末尾换成 `ni`），否则输入法候选确认会被破坏。

**性能**

30. 工具条每次视图更新都刷新，但重活延后到 measure 阶段；诊断探针专门统计 listener 触发次数以排查「update 有没有被调用」。
31. 批注装饰只在 `docChanged` / 显式刷新 / 换文件时重建，`locateAll` 对全文一次性建索引后批量定位。
32. **潜在热点（未解决）**：超长文档每次输入都会重跑 `locateAll`（`tr.docChanged` 分支无节流、无视口裁剪）。改批注性能时从这里入手。
33. 长列表刷新要保滚动位置（编辑台「只同步高亮不重建列表」，搜索时不抢滚动位置）；主页换页动画在后台刷新时不重放。
34. **滚动与坐标的配合**：批注的「上一条 / 下一条」曾无法自动跳转，原因是**从未调用滚动**——`coordsAtPos` 对**视口外**的位置不返回有效坐标。**规则：先把目标滚进视口（`scrollIntoView`）再读坐标**；已在视口内就不要滚（否则会来回抽动）；且必须让路给 `requestMeasure`（更新期间读布局会抛异常）。

**测试与自测手段本身的坑**

35. **测试脚本自己会骗人**：历史上临时写的 CM6 mock，`StateEffect` 的形状是"编的"（与真实不符但断言全过）；测试 harness 的正则因 `lastIndex` 残留**串味**，导致同一断言时对时错。**用 mock 测 CM6 时，先验证 mock 的行为与真实 CM6 一致**，别让"全绿"给你假安全感。
36. **测不到隐藏的面板**：三个批注面板实例并存、两个 `display:none`，测到的那个 `width=0`。先确认测的是哪个实例、是否可见。
37. **CSS 变更无法在 Obsidian 里自动验证**（没有截图能力，也没有 DOM 断言）——见 §3.7，这是本插件最痛的工程约束，务必用「最小改动 + git 整文件恢复」而不是脚本合并。

**基线产生"假数字"的确切历史 bug**

38. **还不知道当前文件时就产生增量** → 会拿「上一个文档」的基线做差，凭空多出几千字（`statusbar.ts:241-246` 注释）。
39. **把基线写到空键上** → 以前 `currentFilePath` 还没建立时基线被写到空路径键上，之后又拿这个键里的（别的文档的）字数做差，**凭空产出 ±几千的假数字**（`statusbar.ts:385-387`）。**现在的规则：空路径一律不记基线。**
40. **重启/跨天把整章当成新写的** → 所以启动时要载入上次会话留下的基线（`statusbar.ts:328`）。

**样式层已修但容易复发的坑（续）**

41. **弹窗尺寸别用 JS 写 inline style** → 快照对比弹窗原由 JS 直接写 `style`，现改为 `.modal.wt-diff-modal` 类（`styles.css:4795` 横幅注明）。同理隐藏态用 `.is-hidden` 类，**不要内联 `style.display`**（旧的 `style.display = ""` 恢复方式不可靠，历史备份里可见这次改写）。
42. **Obsidian 1.14 改了设置页下拉的实现**：不再是原生 `<select>`，也不一定带 `.dropdown` 类，而是 `<button class="combobox-button">`。写相关样式要**三种选择器都覆盖**，别只挑一种（`styles.css:4317-4335`）。
43. **快照对比要临时关掉海明威模式**：否则恢复动作会被 `transactionFilter` 拦掉（`snapshotDiff.ts:341-350`）。
44. **触屏没有 HTML5 拖拽**：桌面用 `draggable` 拖动分卷，手机端必须改用长按菜单里的「移到…」（`workbench.ts:1274-1275`）。
45. **移动端不支持打开系统文件夹**：`Platform.isMobile` 时给 `Notice` 提示（`snapshot.ts:156-159`），不要调用 Electron API。

### 5.3 反复复发的对抗性问题

**为什么「批注」是重灾区**：它同时踩了五个技术面——① 编辑器内浮层随滚动抖动（用户否了两轮）；② 锚点在 Agent 改稿后必然漂移（需要五层定位 + 手动重绑）；③ 装饰重建必须显式触发且要容错拼字/销毁；④ 侧栏面板重绘与跳转时序冲突；⑤ 危险操作确认流程措辞与交互反复调整。**任何"多个 Agent 都改不好"的功能，基本都具备"UI 层 + 数据层 + 时序 + 用户手感"四重耦合这个特征。** 改它之前先把 §3.2「批注的渲染」整节读完。

**为什么「样式」反复回退**：令牌体系（`--wt-*`）+ 主题三色 × 明暗两套 + 移动端 `body.wt-mobile` + Obsidian 自带主题变量 + 内联样式覆盖，五个变量维度相乘。**碰样式前先确认哪个维度在起作用**（用浏览器开发者工具看 `--wt-*` 的实际取值来源最有效），否则「修好这里坏那里」。更底层的困难是 §3.7：**CSS 坏掉是静默的，你看不到 Obsidian 的渲染**，所以只能靠「最小改动 + git 整文件恢复 + 请用户确认视觉」这条慢回路。

**为什么「清理入口」这种"简单任务"也会出事**：历史上出现过「为了简洁删掉多余入口，结果把某功能的所有入口都删光」；同一轮任务里还发生过「理解错需求方向，删错了东西」（用户原话：*「编辑器里的新建批注我要用的，但是侧栏里的不要，你理解错了我的想法」*）。**涉及删除的改动，先把"这一功能现在有哪几条入口/哪几处实现"列出来，删除后立刻验证功能仍可达；需求含糊时先问清，别猜。**

**为什么「统计数字」偶尔对不上**：输入路径有四条（编辑器输入 / 程序化编辑 / 外部 AI 写盘 / 启动补建），每条都要正确区分「算不算、算谁的、算不算时长」。排查时先看 `dailyFileDeltas`（每日各文件明细，专门为这个问题留的）。

**为什么「移动端」特别难**：移动端布局不是媒体查询自动适配的，而是 `body.wt-mobile` + 76 条 CSS 规则**手工铺的一套布局**；多视图并存时还有实例问题（历史上三个批注面板同时存在、两个是 `display: none`，测的那个 `width=0`，整轮排查方向都错了）。抽屉式面板与移动状态栏是**保留的两个备份迭代方向**（`_backup/2026-10-13-mobile-drawer/`、`_backup/2026-10-13-mobile-statusbar/`，后者在 `src/` 里多出 `mobileStatusBar.ts`）。**改桌面端样式时默认会顺带影响手机端**，改完必须用「切换手机版布局预览」命令过一遍。

### 5.4 排查入口速查

| 症状 | 先看哪里 |
| --- | --- |
| 格式工具条不出现 | 跑命令 `格式：自检（排查工具条不出现）`，看落盘报告；再查 `formatToolbarDiag` 的隐藏原因计数 |
| 批注标记/脚注号不显示 | `commentsEnabled` → 是否 `.批注.md` 本身 → `commentStore` 缓存是否加载 → `locateAll` 是否返回空 → `dispatchCommentRefresh` 是否被调 |
| 批注跳不到侧栏 | 面板是否已选中文档（`activeCommentDocPath`）；`revealCard` 的筛选/折叠是否被放开；侧栏 DOM 是否就绪（120ms 重试） |
| 字数统计不对 | `dailyFileDeltas` 明细 → 是否用了 `isDailyCountFile` → 是否刚切过统计模式（基线污染）→ 格式记号是否被剥离 |
| 样式在某个主题下不对 | 开发者工具看 `--wt-*` 取值来自 `styles.css` 还是 `wt-theme-tone.css` 片段；确认 body 上有无 `wt-theme-cool/contrast`、`theme-dark`、`wt-mobile` |
| 手机端布局错乱 | body 是否有 `wt-mobile`；视图是否被 `migrateMobileViewsToDrawers` 挪到抽屉 |
| 数据「丢了」 | `data.json` 是否被 `_backup/` 里某份覆盖；`loadPluginData` 的白名单合并只取 `DEFAULT_SETTINGS` 的键 |

## 7. 待办与已知问题

这些是**当前仍存在**的问题，按优先级排列：

1. **没有任何自动化测试**。`comments.ts`（纯逻辑、文件头明确写了「本模块是纯逻辑，不依赖 Obsidian API，方便单测」）与 `formatWrap.ts`（纯函数）是最值得先补测试的两个模块——引入 vitest + 两个测试文件几乎没有成本，却能挡住锚点定位与格式包裹这两处最易回归的逻辑。
2. **锚点定位的性能**：超长文档每次输入都重跑 `locateAll`，无视口裁剪与节流（见 §5.2 第 32 条）。
3. **隐私残留**：源码注释里还留着真实作品名与角色名——`main.ts:2805`、`main.ts:2840`、`project.ts:19-27`（**本文档已把这些示例改写成虚构名，不要照抄源码原文**）。

4. **文档与实现不一致**：`settings.ts:359` 文案说打字机/沉浸等「命令面板或快捷键切换」，但实际这些开关只存在于侧栏与设置页（`addCommand` 只有 10 处，其中没有这些开关）。

6. **`commentView.ts` 残留未使用的 import**：文件末行是注释「独立侧栏视图『批注』…」，其后没有类定义；顶部 import 的 `ItemView` / `WorkspaceLeaf` 已无使用者（`setIcon` **还在用**，别一起删）。确认后清掉这两个死 import。
7. **确认命令面板是否仍然臃肿**：用户明确要求「保持简洁性」，历史上只保留「工具箱/编辑台/主页/设置」四个入口。当前实际注册 **15 条**命令（5 条入口 + 6 条格式（由 `main.ts:391-400` 的循环生成）+ 1 条格式自检 + 3 条批注）；`addCommand` 调用点是 10 处（循环算 1 处）。新增命令前先想清楚它是否必须出现在命令面板。
   > 历史参考：`_backup/pre-cmd-cleanup-20261015-230516-main.ts` 那次清理删掉了「打开章纲面板」和「批注：打开批注面板」两条命令（批注面板本来就在工具箱里）。
8. **硬编码颜色残留**：`styles.css` 里仍有 **194 个 hex 字面量 + 133 行 `rgb/rgba()`**（多数在主题令牌块内部属正常），散落在规则属性里的部分（`#ffffff` 22 次、`#000000` 21 次等）是历史债。新代码一律走 `--wt-*` 令牌，旧的可渐进迁移。
9. **移动端未在真机验证的路径**：移动端布局靠 `body.wt-mobile` + 76 条 CSS 规则，改动桌面端样式时**很容易顺带弄坏手机端**（媒体查询只有 4 处，不会自动兜住）。桌面调试可用命令「切换手机版布局预览（桌面调试）」。
10. **✅ 已修（2026-10-16）：旧格式用户丢 17 项配置**。原问题：`loadPluginData` 有**两支**，其中
    - **旧扁平格式分支**（判据：`data.json` 顶层直接有 `lineHeight` 或 `paragraphSpacing`）：`themeTone` 与另外 16 个字段被硬写成 `DEFAULT_SETTINGS.xxx`，用户改过的值在加载时被默认值顶掉，接着被 `savePluginData` 的整文件覆盖写回 `data.json` —— **一次性、不可逆**的配置丢失。
    - **白名单合并分支**（正常格式走这里）**本来就没问题**。
    **修法**（已落地）：在该分支的对象字面量之后补一次读取——`{ ...data.settings, ...data }` 作为「扁平键优先」的来源，逐项恢复这 17 个字段（缺字段仍回落默认值）。见 `main.ts` 的 `legacyFlat` / `restoreFromLegacy`。
    **这次修复有回归验证**：抽出真实的 `loadPluginData` 方法体跑了两组对照——修复前该用例 **17 项全丢**，修复后 **17 项全保留**，并且「缺失字段回落默认值」「白名单合并分支不受影响」「无数据不抛异常」三个回归用例都通过。
11. **✅ 已修（2026-10-16）：`CommentStore` 删除后缓存粘滞**。原问题：`handleDeleted` 往缓存里写**空数组**，该条目会一直粘到下一次 `create`/`modify`/`rename`，且没有边界。**修法**：改为 `invalidate`（不写空缓存）。行为不变（文件确实不在时下一次 `load` 读到的仍是空列表），但去掉了无边界粘滞。**已用真实 `CommentStore` 实现跑 11 个用例验证**（删除/重建/改名/modify/save 空与非空/并发读取复用）。
    > 复核时曾把这条判为「需引用功能先失效」——那部分其实已由 `main.ts:560` 的 `create` 处理器覆盖。**真正的收益是边界**，不是「重命名后读不到」。
12. **`isDraftPath` 有三套语义不一致的实现**（代码显式，非推断）：`outlineText.ts:153-155`（空关键词 → `true`）、`chapterOrder.ts:274-275`（空关键词 → `false`）、`snapshot.ts:30-38`（**硬编码「正文草稿」、完全不看设置**）。**「正文草稿」这个概念的判定在三个地方定义不同**，任何涉及草稿识别的改动都要三处一起核对，否则会出现「章节列表认它、快照不认它」这类错位。
13. **已知的数据静默丢失窗口**：`data.json` 落盘有 **2 秒防抖**（`main.ts:2538-2545`，`onunload` 兜底一次），崩溃会丢最后 2 秒统计；`statusbar.ts:46-47` 的**基线内存上限 400**，超出会静默漏计旧文件增量；`data.json` 是**全量覆盖写**，多端同步（如坚果云）冲突时「后写赢」。

15. **后台编辑器的批注跳转**：在非活动文档的编辑器里点批注标记，`revealCommentInPanel` 用了**活动文档**的数据源，`revealCard` 找不到卡片会静默返回（`main.ts:1917` 的 `void path` 未使用）。修法是让面板按传入的 `path` 取数据。
    > **同一个根因还有个更严重的后果**：批注面板的**所有**操作（编辑、删除、标记已处理、重新绑定）用的都是活动文档（`main.ts:1767`、`1790`、`1801`、`1811`、`1864`、`1967`）。所以在 A 文档的面板上操作时若焦点已经飘走，「删除」可能删到 B 文档的批注。**修这一条要连坐处理，别只修跳转**——这块需要改面板与宿主的接口（把文档路径显式传下去），会动到批注的核心交互，建议单独一轮做并手工回归。
