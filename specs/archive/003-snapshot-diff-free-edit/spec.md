# SPEC-003 · 快照对比改为双栏自由编辑

> 一句话：把快照对比弹窗从「逐块对齐、右侧按段编辑」改成左右两栏连续可滚动的编辑器——左侧旧稿任意选中复制，右侧当前正文直接自由编辑——让快照窗口符合「拿旧稿改新稿」的直觉。
>
> 分级：M ｜ 状态：done ｜ 创建：2026-10-19

## 1. 问题与动机

快照功能目前的唯一复制入口是弹窗里的「复制快照」按钮：**一次只能复制整份旧稿**。真实修文时用户要的是「旧稿里某一段 / 某一句写得好，选中复制，粘到当前正文里」，整章复制反而要再手工裁剪，等于没用。

同时对比弹窗的编辑体验是**按段落块**做的：每段是一个独立的 `contenteditable` 单元，段落之间不能连续选择，回车会在块内制造新行，跨段删除 / 粘贴行为都不像编辑器。用户原话：

> 我希望对比弹窗里面能自由的选择任意文字，就像常规的编辑体验一样。甚至能直接在这个对比窗口里面，对目前的正文进行编辑。

根因在实现方式：`src/snapshotDiff.ts` 把 diff 结果渲染成左右各一列 `.wt-diff-line`，右侧每行一个 `contenteditable` 单元（`data-unit-index`），编辑回写靠 `composeEditedText()` 逐单元拼装。逐行对齐（LCS 块）与整篇连续编辑在同一个 DOM 结构里互斥——用户已确认选择「两栏各自连续滚动」。

## 2. 用户场景

- 当我对比一份旧快照想沿用其中一段时，我想在左侧旧稿里像读普通文档一样选中一段并复制，以便直接粘到当前正文，而不是复制整章再删。
- 当我在对比时发现当前正文某处要改，我想直接在右侧敲字、回车分段、删掉整段，改完一键写回文档，以便不用关掉弹窗回编辑器再改。
- 当我想确认改了什么，我希望改动处在两侧用颜色标出来，而不是靠肉眼逐行比对。
- 当我在手机上打开对比时，我希望两栏能上下叠放，仍然可以选中复制和编辑。

## 3. 需求

### 功能需求

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-001 | 对比弹窗左右两栏各自连续滚动：左栏展示快照全文（只读），右栏展示当前正文全文 | 必须 |
| FR-002 | 左栏文字可以像普通文档一样任意选中（拖选、双击选词、跨段选择）并复制 | 必须 |
| FR-003 | 右栏是纯文本编辑区：回车分段、粘贴、跨段选择删除都按编辑器直觉工作，不产生块级 DOM 结构 | 必须 |
| FR-004 | 差异以行内高亮标出（删除 / 新增 / 修改三色），右栏编辑后自动重算，不要求用户点「重新对比」 | 必须 |
| FR-005 | 提供「复制选中」：复制左右任意一栏当前选区；没有选区时给出提示而不是静默复制全文 | 必须 |
| FR-006 | 保留「复制快照」整份复制入口 | 必须 |
| FR-007 | 右栏编辑**自动写回**源文档：停止输入约 1 秒后自动保存，按钮「保存」与 `Cmd/Ctrl+S` 可立即保存；沿用程序化编辑（可撤销）、海明威模式临时关闭；若源文档被外部改动，拒绝写入并提示 | 必须 |
| FR-010 | 保存状态在弹窗内可见：`已保存 / 未保存 / 正在保存… / 保存失败`，且输入瞬间即变「未保存」 | 必须 |
| FR-011 | 一次对比会话只生成一份备份快照（不得因自动保存反复备份而挤掉历史版本） | 必须 |
| FR-008 | 「重置为快照」把右栏替换为快照内容；右栏有未写入修改时先确认 | 必须 |
| FR-009 | 关闭弹窗时若右栏有未写入修改，先确认；确认放弃后关闭，不静默丢改动 | 必须 |

### 非功能需求

| ID | 需求 | 说明 |
| --- | --- | --- |
| NFR-001 | 高亮不污染 DOM：不得为标色把正文包进 span 或拆成逐行节点，否则复制会带出多余换行 | 用 CSS Custom Highlight API，只注册 Range |
| NFR-002 | 不新增 Obsidian 命令、不改 `data.json` 结构、不新增设置项 | 见宪法 #3、#5 |
| NFR-003 | 样式走 `--wt-*` 令牌与既有 `--background-*`，覆盖暗色 / 高对比度 / `body.wt-mobile`（手机端两栏上下叠放） | 见宪法 #8 |
| NFR-004 | 环境不支持 Highlight API 时降级为无高亮的纯文本双栏，功能可用且不报错 | Obsidian 桌面与移动端均为 Chromium ≥105，降级只作兜底 |
| NFR-005 | 环境不支持 `contenteditable="plaintext-only"` 时右栏必须退回可编辑的普通可编辑区（不能静默变只读），并按 `innerText` 读全文 | 不支持的浏览器会把该属性解析成**不可编辑**（实测 `isContentEditable === false`），用户会以为功能坏了 |

## 4. 验收标准

| ID | 验收标准 | 验证方式 |
| --- | --- | --- |
| AC-001 | 差异区间计算正确：完全一致时无区间；整段改写时左右各自覆盖该段；只删 / 只增时只在一侧出现；单段改写时区间收窄到字符级且都在文本范围内、互不重叠 | 自动：`tools/checks/check-snapshotdiff.js` |
| AC-002 | 双栏结构符合自由编辑要求：右栏用 `contenteditable="plaintext-only"`，不再有逐段 `data-unit-index` 单元；两栏样式声明 `user-select: text`；高亮走 `::highlight(wt-diff-*)` 且注册用 CSS Custom Highlight API；「复制选中」入口存在 | 自动：`tools/checks/check-snapshotdiff.js` |
| AC-003 | 写回保护仍然成立：写回前比对基线文本，源文档被外部改动时拒绝写入并提示；首次写回前仍保存当前版本为快照 | 自动：`tools/checks/check-snapshotdiff.js` |
| AC-009 | 自动保存可用：输入后停顿约 1 秒自动写回文档；`Cmd/Ctrl+S` 与「保存」按钮立即写回；保存后状态变「已保存」 | 自动：`tools/checks/check-snapshotdiff.js`；人工：Obsidian 中打开对比窗，在右栏改一句后停手，等约 1 秒再关窗重开该文档，看改动是否已在正文里 |
| AC-010 | 一次会话只备份一次：连续多次自动保存后，备份快照调用次数为 1（不会挤光 20 份保留上限） | 自动：`tools/checks/check-snapshotdiff.js` |
| AC-011 | 关窗不丢内容：有未保存修改时关窗先尝试保存，保存成功直接关；仍失败才弹确认 | 自动：`tools/checks/check-snapshotdiff.js` |
| AC-004 | 命令面板仍只有四条白名单命令，未因本次改动新增入口 | 自动：`tools/checks/check-commandsurface.js` |
| AC-005 | 类型检查、构建与全部逻辑检查通过 | 自动：`npm run check`；`npm run verify` |
| AC-006 | 真机：在 Obsidian 打开任一章节的快照对比，左栏拖选跨段文字后 Cmd/Ctrl+C 能粘贴到正文；右栏回车分段、删除整段、粘贴都正常；改动处三色高亮随输入更新；「应用到文档」写回后 Ctrl+Z 可撤销；关窗时有未写入修改会先确认 | 人工：Obsidian 中打开工具箱 → 快照 → 点任一行进入对比，按上述步骤逐项操作并观察 |
| AC-008 | 右栏不因 `plaintext-only` 不受支持而变成只读：源码里有运行时探测，探测失败退回 `contenteditable="true"`，且读全文走 `innerText` | 自动：`tools/checks/check-snapshotdiff.js` |
| AC-007 | 真机：暗色 / 高对比度主题下两栏底色与高亮可读；窗口收窄到手机宽度（或 `body.wt-mobile`）时两栏上下叠放，仍可选中复制与编辑 | 人工：Obsidian 中分别切到暗色与高对比度主题打开对比窗，再用开发者工具把窗口收窄到 390 宽（或给 body 加 `wt-mobile`）复看两栏布局 |

## 5. 非目标

- 不做侧栏快照列表的行内「复制」按钮（本次只改对比弹窗）。
- 不把「自动保存」做成可配置项（不做设置项，阈值写死 1 秒）；不改快照自身的自动触发策略。
- 不做左右两栏滚动同步、不做多快照并排对比、不做词级 / 行级双模式切换。
- 不改快照文件命名、存储目录、保留策略与任何设置项。
- 不引入语法高亮或 Markdown 预览渲染，两栏都是纯文本。

## 6. 影响面与约束

- 模块归属：只改 `snapshots.ui` 的对比弹窗实现（`src/snapshotDiff.ts`）与其样式；`SnapshotOperations` / `SnapshotDiffHost` 窄接口保持不变，核心模块与侧栏面板不受影响。见宪法 #4。
- 数据与设置：无变化；`data.json` 不新增键。见宪法 #5。
- 命令面：不新增命令。见宪法 #3。
- 样式：新增 `.wt-diff-pane` 与 `::highlight(wt-diff-*)`，移除已无引用的逐行 diff 样式；只做局部替换，不大范围重写 `styles.css`。见宪法 #8。
- 编辑器安全：写回仍走「程序化编辑」通道（`markProgrammaticEdit` + 临时关闭海明威），见设计文档 §3.4、§4.1 禁忌 43。
- 自动检查：扩展 `tools/checks/check-snapshotdiff.js`（纯逻辑 + 源码 / 样式静态断言），需要反向验证。见宪法 #12。

## 7. 开放问题

| 问题 | 结论 |
| --- | --- |
| 逐行对齐与整篇连续编辑能否兼得 | 不能（同一 DOM 结构互斥）；用户已确认选「两栏各自连续滚动」，差异用颜色表达 |
| 手机端两栏怎么放 | 上下叠放各占一半高度，保留选中与编辑能力 |
