# SPEC-001 · 高对比度主题复刻 Notion 皮肤，并统一移动端形态

> 一句话：把「高对比度」从纯黑白换成按真实 Notion 高对比度皮肤逐像素取色的完整复刻，并补齐手机端与窄屏设置页的形态对齐。
>
> 分级：L ｜ 状态：verifying ｜ 创建：2026-10-18

## 1. 问题与动机

此前的高对比度主题只是把纸面与文字换成纯黑 / 纯白，组件（按钮、开关、标签、选中态、卡片）
仍沿用暖纸主题的形态；同时它有两份令牌：`styles.css` 的 `body.wt-theme-contrast` 块，与
`src/themeSnippet.ts` 生成的首帧 CSS 片段（片段带 `!important`，先于插件 JS 生效）。

这带来三个真实问题：

1. **换肤只换了一半**：纯黑白 + 旧组件形态既不像用户给出的 Notion 高对比度皮肤，也没有
   真正的层次（卡片、按钮、开关、标签仍是暖纸风格）。
2. **两份令牌会静默漂移**：只改 `styles.css` 不重编片段，界面**一点变化都没有**。
   2026-10-18 换 Notion 配色时实际发生过（片段仍是旧的纯黑值）。
3. **手机端与窄屏没有跟着换**：手机独有的底部导航、FAB、状态条不在桌面组件规则覆盖范围内；
   窄屏设置页还会因 `flex-basis` 在 column 布局下变成高度，凭空多出 260px 空白（2026-10-19 用户反馈）。

## 2. 用户场景

- 当我需要高对比度阅读时，我希望浅色是「白纸 + 深灰字 + 发丝线」、深色是「炭黑纸 + 近白字」，
  而不是刺眼的纯黑纯白，以便长时间写作不累眼。
- 当我切到高对比度时，我希望按钮、开关、标签、选中态和卡片都换成同一套皮肤形态，
  而不是只换颜色、组件还是旧样子。
- 当我在手机上写作时，我希望底部导航、FAB、状态条和桌面看起来是同一套主题，
  而不是残留上一版的毛玻璃 / 光晕。
- 当我在窄窗口 / 手机上打开设置时，我希望每个下拉项正常占一行，而不是多出一大块空白。

## 3. 需求

### 功能需求

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-001 | 高对比度浅色复刻 Notion 皮肤：`#ffffff` 白纸、`#f9f8f7` 奶白面板、`#202020` / `#5f5e58` / `#8d8b85` 三档文字、`rgba(55,53,47,.22)` 发丝线；卡片平铺、无投影 | 必须 |
| FR-002 | 高对比度深色用炭黑纸 `#191919`（不是纯黑）、`#252525` 卡片、近白字与同强度发丝线 | 必须 |
| FR-003 | 组件形态跟随皮肤：主按钮暗蓝实心、次按钮幽灵形态、开关暗蓝轨道 + 白滑块、视图标签药丸选中、输入框 / 下拉白底发丝边、行分割线直角 | 必须 |
| FR-004 | 首帧片段（`src/themeSnippet.ts`）与 `styles.css` 的令牌值一致（片段是 `styles.css` 的子集，比较时忽略空白与大小写）：冷调 / 高对比 × 明暗主令牌、窄栏墨色、热力图、四个面板底色 | 必须 |
| FR-005 | 手机端三处与桌面形态对齐：底部导航（实色、无分割线、无毛玻璃）、FAB（暗蓝实心、无光晕）、底部状态条（进度 / 达标 / 轨道与桌面同色） | 必须 |
| FR-006 | 窄屏设置页：下拉项不出现 260px 空白；设置行分割线两端不翘成圆弧 | 必须 |
| FR-007 | 高对比度下编辑器正文不接管背景：浅色走白纸、深色走炭黑，与 Obsidian 原生背景自然衔接 | 必须 |

### 非功能需求

| ID | 需求 | 说明 |
| --- | --- | --- |
| NFR-001 | 不新增命令 / 视图 / 页面入口 | 命令面板仍只有四条白名单命令（宪法 #3） |
| NFR-002 | 首帧不闪回暖纸 | 沿用 localStorage 主题缓存 + 片段同步机制（设计文档 §3.5） |
| NFR-003 | 样式最小改动 | 不重写 `styles.css`；新颜色走 `--wt-*` 令牌；不新增散落的裸 hex（主题令牌块内部除外） |

## 4. 验收标准

| ID | 验收标准 | 验证方式 |
| --- | --- | --- |
| AC-001 | 首帧片段与 `styles.css` 的冷调 / 高对比令牌逐项一致（27 条断言全过），且把 `styles.css` 副本改坏后检查会变红 | 自动：`tools/checks/check-theme-palette.js` |
| AC-002 | 窄屏 `flex-basis` 改回 `auto` 并铺满；设置行、工具箱 / 主页设置行都不带宿主圆角（3 条 CSS 断言通过） | 自动：`tools/checks/check-settingcontrols.js` |
| AC-003 | 桌面浅色 / 深色逐页检查：主页、编辑台、工具箱、设置页的卡片无投影，按钮 / 开关 / 标签 / 选中态符合皮肤 | 人工：Obsidian 切到高对比度，分别在浅色、深色主题下打开四个页面逐项核对 |
| AC-004 | 手机预览 390×844 下，底部导航 / FAB / 状态条与桌面形态一致，无毛玻璃、无光晕残留 | 人工：Obsidian 开发者工具 Console 执行 `document.body.classList.add('wt-mobile')`，把窗口收窄到 390×844，逐页查看底部导航 / FAB / 状态条三处，看完执行 `remove` 还原 |
| AC-005 | 窄窗口（≤400px）设置页每个下拉设置项正常一行，无 260px 空白；行分割线为直线 | 人工：把设置弹窗收窄到手机宽度，逐个下拉项与行分割线检查 |
| AC-006 | 冷启动 / 重载时首帧不闪回暖纸 | 人工：在高对比度下退出并重开 Obsidian，观察首帧 |
| AC-007 | 命令面板仍只有四条白名单命令，未因换肤新增入口 | 自动：`tools/checks/check-commandsurface.js`、`tools/checks/check-boundaries.js` |

## 5. 非目标

- 不新增第五种配色主题，也不改「暖纸 / 冷淡」两套既有配色。
- 不接管 Obsidian 默认主题 / 第三方主题下的编辑器配色（维持现有生效范围）。
- 不重写 `styles.css` 的结构，只做令牌与组件规则的增量修改。
- 不做主题自定义（用户不可编辑色板）。

## 6. 影响面与约束

- **模块归属**：`appearance.typography`（Feature Module）负责首帧片段；`styles.css` 负责页面与组件样式；**不涉及** Host / Services / 数据。
- **数据与设置**：无新增设置项，`data.json` 结构不变；主题值仍是 `themeTone: warm | cool | contrast`。
- **命令面**：不变（宪法 #3）。
- **样式与手机端**：只改主题令牌块与组件规则；必须检查浅 / 深 × 冷调 / 高对比 + `body.wt-mobile`（宪法 #8）。
- **隐私**：本文与代码示例一律虚构名（宪法 #9）。

## 7. 开放问题

| 问题 | 结论 |
| --- | --- |
| 新增的 `--wt-action` / `--wt-selected` 等令牌是否要进首帧片段？ | 不进。它们只用于插件视图渲染后的组件，首帧用不到；片段只负责会闪的纸面 / 文字令牌。 |
| 深色纸为什么用 `#191919` 而不是纯黑？ | 与 Notion 深色皮肤一致，且与 Obsidian 原生背景衔接更自然；纯黑在 OLED 上对比过强。 |
