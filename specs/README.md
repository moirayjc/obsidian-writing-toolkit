# 规格（spec）

> 2026-10-20 起再次简化：去掉门禁、编号、状态和收尾仪式，只留「动手前对齐」这一件事。

## 什么时候写

只问一句：**实现之前，需要作者确认要不要这样做吗？**

- **不需要**（修 bug、重构、性能、补检查、文档、样式 / 文案修正）：直接做，提交信息写清现象 / 根因 / 怎么验证。
- **需要，但范围小**：在对话里把「做什么 / 不做什么 / 怎么算完」复述一遍，作者确认后再动手，不写文件。
- **需要，且范围大或要跨会话**（新功能、改 `data.json` 结构 / 设置项、用户会察觉的行为变化）：
  照 [`_template.md`](_template.md) 在本目录随便建一个 md，三节写完，作者确认后再动手。

## 规矩

1. 作者确认之前，不写实现代码。
2. 范围变了，先改 spec（或在对话里重新确认），再改代码。
3. 实现中发现的坑和约定，顺手写进 `docs/插件设计文档.md` 或 `AGENTS.md`。

文件名、格式不做检查，也没有状态字段；做完就做完了，不用回来改。
