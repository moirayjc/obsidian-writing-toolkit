# 批注改为多轮对话（作者 / Agent 双向批注）

> 2026-10-22 作者确认。
> 目的：Agent 一次给一大堆意见时，不在聊天框里逐点回复，而是落到正文对应位置，按点多轮讨论，直到作者满意。
> 典型流程：Agent 通读无批注的文章发起一批批注 → 作者在面板里逐条回复 → Agent 再回一轮 → …… → 作者逐条点「已解决」/「不采纳」。
> 作者与 Agent 轮流写批注文件，不会同时写。

## 做什么

### 数据（批注文件格式）

- 每条批注 = 锚点（原文 / 段落 / 现文 / 位置）+ 发起人 + 一串按时间顺序的消息。
- 消息一行一条，标签就是说话人：`- 作者：……` / `- Agent：……`，可以重复多次，按出现顺序就是对话顺序；多行沿用「两格缩进续行」。
- **去掉「状态」字段**。「轮到谁」由最后一条消息的说话人推出：最后是作者 → 等 Agent；最后是 Agent → 等作者。
  Agent 没有任何可改的状态字段，从根上避免它自己结案。
- 新增 `- 发起：作者 | Agent`，只用于显示。
- 文件末尾新增「已否决」区：`## 已否决` 下每行一条 `- 「原文」：首条意见（截断）`，给 Agent 下一轮看，避免重复提。
- 示例：

  ```
  ### 批注 3
  - 发起：Agent
  - 原文：雨下到第七天
  - 段落：雨下到第七天，渡口的船都歇了。
  - 现文：
  - 位置：第 2 段 · 约第 5 行
  - 创建：2026-10-22 14:00
  - Agent：开头节奏偏慢，建议直接进人物动作。
  - 作者：同意进动作，但别删「第七天」。
  - Agent：改写方案：……

  ## 已否决
  - 「船都歇了」：这里换成更具体的声音
  ```

- 旧格式兼容（只读时转换，下次保存写成新格式）：`内容` → 第一条消息（说话人按「发起」，缺省为作者）；`回复` 非空 → 追加一条 Agent 消息；`状态` 忽略。
  旧的「已处理」条目因此变成「等作者」，由作者自己点已解决清掉。

### 给 Agent 的协议（文件抬头 + 面板复制的指令）

- 发起批注：「原文」必须从正文**逐字复制**，取一句里有区分度的短片段；「段落」照抄整段；同一处已有批注时，在那条里追加消息，不新开；不提「已否决」区里的意见。
- 每轮回复：只回**最后一条是作者**的批注，在末尾追加一条 `- Agent：`；不改、不删任何已有消息，不删条目，不碰「已否决」区。
- 讨论中只在消息里给改写方案，**不动正文**；作者在消息里明确说改（「改」「就这样改」之类），才改正文，并把改完后该处的文字覆盖进「现文」。
- 面板底部的「复制处理指令」拆成两个按钮：
  - 「复制批注指令」：请 Agent 通读本文、按上面规则发起批注（文章已有批注时同样适用，Agent 只补新的）；
  - 「复制回复指令」：请 Agent 处理所有等 Agent 的批注，并写明当前条数。

### 面板（工具箱「批注」标签）

- （已被下面「标签 → 列表 → 单条详情」取代）每张卡片显示原文引用 + 对话气泡（作者 / Agent 左右或配色区分），底部一个**多行**回复输入框（回车换行，按钮发送）。
- 卡片标注「等你」/「等 Agent」；列表「等你」排在前面，组内按正文位置排。标签徽标显示「等你」条数。
- 卡片操作只保留：
  - **已解决**：整条从批注文件删除，不归档。沿用现有「一次确认 + 6 秒内可撤销」。
  - **不采纳**：整条删除，并在「已否决」区追加一行。同样可撤销。
  - 编辑 / 删除**自己最后一条**消息（Agent 回复后就不能再改了）。
- 原来的「标记已处理 / 重新打开」「删除」「只看待处理」「已处理折叠分组」「清除已处理」全部去掉。
- 作者在正文选中文字新建批注，和现在一样，只是成为该条的第一条作者消息。
- 定位不到原文的批注（多见于 Agent 抄错原文）照常显示在列表末尾，标「无法定位」，可以手动重新绑定（现有能力），不丢。

### 面板改为「标签 → 列表 → 单条详情」（2026-10-22 试用后补充，作者确认）

- 列表页顶部三个可点标签：「等你 N」「等 Agent N」「全部 N」，默认「等你」（没有等你的就「全部」）。
- 标签下每条一行：`#编号`、原文片段、最后一条消息开头；原文已删除 / 无法定位的行尾带小标记。点一行：编辑器跳到那处并选中，侧栏进入这条的详情页。
- 「复制批注指令」「复制回复指令」只在列表页底部。
- 详情页：顶部「← 返回」「#编号」「状态」「定位」（回到正文那处）；下面是原文、完整对话、回复框、「已解决 / 不采纳 / 编辑 / 重新绑定」。详情页里点内容**不跳转**，原文与对话可以选中复制。点「已解决 / 不采纳」后回到列表。
- 正文里点批注标记 / 脚注号 → 侧栏直接打开这条的详情页。切换文档 → 回到列表。回复发出、Agent 改了批注文件 → 详情页原地刷新，不跳回列表（正在写的回复和输入焦点保留）。

### 只在桌面端 + 面板美化（2026-10-23 作者确认）

- 移动端（`Platform.isMobile`，与计划看板同一口径）不提供批注：工具箱没有「批注」页，编辑工具条没有批注按钮，长按菜单没有「添加批注」，正文不画批注痕迹。原因：批注文件在隐藏目录 `.wt-comments/`，作者的同步方案不同步它，手机上写的批注会孤立在手机里；手机端主要用来修文和语音录灵感。
- 面板沿用工具箱的视觉语言：标签用分段控件、列表与详情各是一张纸卡、按钮清掉宿主冷灰底（幽灵按钮 / 强调色实心「发送」）；Agent 消息浅底块、作者消息强调色竖线，都占满整行。暖纸 / 冷淡 / 高对比 / 暗色都要过一遍（预览：`.wt-preview/comment-panel/render.mjs`）。

### 作者亲手改正文时，批注跟着走（2026-10-22 试用后补充，作者确认）

- 作者在编辑器里改正文时，批注位置跟着改动走（不再每次按键拿「原文」全文找）；停手约 1.5 秒、失焦或换文件时，把这处现在的文字写进「现文」，并更新「段落 / 位置」。「原文」不动，留给 Agent 看当初说的是哪句。
- 批注圈住的文字被整段删掉：写入 `- 原文已删除：是`，定位到删除处所在的段落（不再拿原文全文找，免得同样的字把它指到别处）；卡片标「原文已删除 · 改完了就点『已解决』」。重新绑定会清掉这个标记。
- 只跟踪作者的输入（打字、删除、粘贴、拖放、撤销）；外部改文件后重载进编辑器的改动不映射，回到按文字定位。
- 协议与指令补充：Agent 定位先找「现文」再找「原文」；都找不到就在回复里说明，**不许改写「原文」「段落」去指向别的句子**。

### 防 Agent 越权

- 插件写批注文件前**先重新读盘**再合并，不用内存里的旧列表整份覆盖。
- 批注文件被外部改写时，插件和改写前的缓存比较：如果有条目消失、已有消息被改，弹一条提示（「Agent 删除 / 改写了批注 N」）并提供「恢复」。不自动回滚。

### 加回「删除」（2026-10-25 作者确认）

- 只有「已解决」时，作者找不到删除入口：比如批注了一段，后来发现要连下一段一起圈，想删掉这条重来，
  但「已解决」的字面意思是「讨论完了」，看不出它就是删除。
- 详情页 / 页边卡的按钮行加「删除」，放最右、淡色：一次确认（3 秒）+ 6 秒内可撤销；整条删掉，**不**记进「已否决」，提示「批注 #N 已删除」。
- 「已解决」「不采纳」不变。「重新绑定」仍只在原文已删除 / 无法定位时出现（改成每条都能「改范围」作者暂未要）。
- 验证：`check-comment-margin` 新增 3 条（反向验证：删除不经确认 / 当成不采纳，各自报警）；作者在测试库试过删除、确认、撤销，没问题。

## 不做什么

- 不做实时聊天、不由插件调用 Agent；Agent 的每一轮都由作者在 Agent 里发起。
- 不归档已解决的批注，不做历史记录。
- 不处理作者与 Agent 同时写同一批注文件的冲突合并（流程上轮流写）。
- 不改正文零污染原则、批注文件位置（`.wt-comments/`）、定位算法、正文里的标记与脚注号样式。
- 不改 `data.json` 结构，不加设置项，不注册命令。
- 不做每条消息的时间戳（`10:00` 里的冒号会撞字段解析，收益也小）。
