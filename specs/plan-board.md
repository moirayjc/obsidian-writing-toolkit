# 写作计划看板

> 2026-10-22 作者提出：主页加「待写 / 在写 / 完成」三列看板，全局一份，要日期。
> 2026-10-22 作者确认：看板独立成第五页 + 书桌摘要卡；文件放「1-写作」文件夹根目录；v1 不关联作品。

## 做什么

**入口**

- 主页左侧导航列新增第五页「看板」（排在「书桌」之后），不注册命令；命令面板仍只有四个入口。
- 书桌页新增一张「计划」卡：只列**已逾期、今天到期、在写**的条目（最多 5 条，多了显示「还有 N 条 ›」跳到看板页），每条前面有勾选框，勾上即移到「完成」。卡片头部有「看板 ›」链接。
  书桌宽屏排法变为：「正在写 | 今日进度」「最近七天 | 计划」「其他在写的书（整行）」；窄屏按此顺序叠成一列。

**看板页**

- 三列：待写 / 在写 / 完成，列头显示条数。
- 每条卡片：一行文字（必填）+ 截止日期（可选）。日期显示为「今天 / 明天 / 周五 / 10月25日」；逾期标红、今天到期标强调色；完成的条目显示完成日期。
- 列内排序：有日期的按日期从早到晚在前，无日期的按添加顺序在后；「完成」列按完成时间从新到旧。
- 「完成」列只展开最近 7 天完成的，更早的折叠成「更早完成 N 条」，点开可看；不自动删除。
- 新增：「待写」「在写」列底部「＋ 添加」（「完成」列不设添加，直接加进完成没有意义），输入文字回车即加；日期在卡片上点「日期」选（原生日期选择器），可清除。
- 移动：桌面端可以把卡片拖到别的列（列内顺序由日期决定，不能拖）；桌面端和手机端都可以点卡片右侧「⋯」或右键：移到待写 / 在写 / 完成、改日期、编辑文字、删除。
- 删除：不弹确认，底部提示「已删除」+「撤销」（几秒内可撤回）。
- 看板页宽度不够三列并排时（窄窗口 / 手机），改成顶部分段切换「待写 / 在写 / 完成」，一次看一列。

**数据**

- 存在库里的一个 Markdown 文件，默认 `1-写作/写作看板.md`，路径可在设置页改；文件不存在时首次添加条目才创建。
- 文件格式人能直接读写，手改也能被看板认出：

  ```markdown
  ## 待写
  - [ ] 第十二章打斗收尾 📅 2026-10-25
  - [ ] 整理配角设定
  ## 在写
  - [ ] 第三卷大纲 📅 2026-10-30
  ## 完成
  - [x] 修改第十一章节奏 ✅ 2026-10-22
  ```

  （📅 / ✅ 与 Tasks 插件写法一致。）认不出的行原样保留，不丢内容。
- 随网盘同步跨设备：文件被外部修改（同步、手改）后，看板和书桌卡片不用重启就刷新。不写 `data.json`（唯一新增的设置项是文件路径）。

## 不做什么

- 不关联作品 / 章节（v1 只有文字 + 日期；需要的话把书名写进文字里）。
- 不做提醒通知、重复任务、优先级、标签、子任务、自定义列。
- 不做列内手动排序。
- 不把看板条目算进字数、时速、目标统计。
- 不注册任何命令；不新增工具箱侧栏或编辑台入口。

## 怎么算完

- [x] `npm run verify` 全部通过，命令面板仍只有四个入口；新增检查覆盖：看板文件解析 / 写回往返不丢行（含认不出的行、手写的乱序段落）、跨列移动、日期解析与「逾期 / 今天 / 明天」判定、完成时写入完成日期、改回未完成时去掉完成日期、新设置项按 `data.x ?? DEFAULT` 加载
- [ ] 测试库 Obsidian：看板页添加、改日期、拖到「在写」、勾选完成、删除后撤销，`1-写作/写作看板.md` 内容随之正确变化
- [ ] 手改 `写作看板.md`（加一行、挪段落）→ 看板与书桌「计划」卡即时刷新
- [ ] 书桌「计划」卡：逾期 / 今天 / 在写条目出现，勾选后消失并进入完成列
- [ ] 窄窗口与 `body.wt-mobile` 下看板改为分段切换，「⋯」菜单可移动条目；暗色 / 冷淡 / 高对比主题显示正常
- [ ] 设置页改看板文件路径后，看板读写新文件

## v2：做成真正的看板（仅桌面端）

> 2026-10-22 作者反馈「现在这个看板其实很难说是看板」；确认先只做桌面端。
> 本节覆盖上文中与之冲突的条目（列内排序、关联作品、窄屏分段切换、手机端）。

### 做什么

- **只在桌面端**：手机端不显示「看板」导航项和书桌「计划」卡（看板文件照常同步，不受影响）。
- **铺满页面**：看板页不限 1040px 宽，三列撑满主区高度，每列自己上下滚动；窗口太窄时三列横向滚动，不再切成一次一列。
- **列内手动排序**：卡片可以在列内上下拖、拖到别的列的任意位置，拖动时显示插入线；顺序就是看板文件里的行序。日期只做提醒，不再决定顺序。勾选完成的卡片排到「完成」列最上面。
- **卡片**：标题（最多两行）、备注摘要（最多两行）、底部一排标签：作品（颜色与该书封面色一致）、关联章节（点一下打开那章）、截止日期。
- **卡片详情**：点卡片打开详情窗，可改标题、备注（多行）、截止日期、作品、关联章节（从该书章节里选），也可在这里删除。
- **按作品筛选**：顶部「全部 / 各本书」，只显示该书的卡片；筛选中新添加的卡片自动归到这本书。
- **文件格式**（仍是普通 Markdown，手改也认得）：

  ```markdown
  - [ ] 第十二章打斗收尾 [[第十二章 夜雨]] 📚 某部作品 📅 2026-10-25
    先写主角受伤，再写援兵到
  ```

  章节是行尾的 `[[链接]]`（在 Obsidian 里本身可点）；作品是 `📚 书名`；备注是条目下面缩进的行。

### 不做什么

- 手机端的任何看板交互；自定义列、WIP 上限、泳道、子任务、提醒。

### 怎么算完

- [x] `npm run verify` 全部通过；检查覆盖：列内 / 跨列插入到指定位置、同原文条目拖动不串位、作品 / 章节 / 备注的解析与写回、改备注不动其他行
- [ ] 测试库：列内上下拖、跨列拖到中间位置，插入线位置与落点一致，`写作看板.md` 行序随之变化
- [ ] 卡片详情改标题 / 备注 / 日期 / 作品 / 章节后，卡片与文件都正确；点章节标签打开那章
- [ ] 作品筛选只显示该书卡片；筛选中添加的卡片带上这本书
- [ ] 窄窗口三列横向滚动；暗色 / 冷淡 / 高对比主题显示正常

> 2026-10-22：v2 实现完成，`npm run verify` 46 项全过（`check-plan-board.js` 57 条，已反向验证）。Obsidian 里的人工回归**还没做**。

## v3：章节卡

> 2026-10-24 作者确认：章节可以直接作为看板卡片；拖进「完成」= 定稿；暂不支持还没创建的章节；卡片信息按提案。

### 做什么

- **章节卡**：整行只有一个 `[[链接]]` 的条目就是章节卡（`- [ ] [[第十二章 夜雨]] 📚 某部作品 📅 2026-10-25`）。
  卡片标题是章节名，下面一行显示字数与上次修改时间，定稿的章节标题旁有锁；作品、截止日、备注照常。
- **点章节卡直接打开这一章写作**（同时把这本书设为正在写的书）；详情窗改从「⋯」/ 右键打开。书桌「计划」卡里的章节行点一下也打开这一章。
- **添加章节**：「待写」「在写」列底部多一个「＋ 添加章节」，从当前筛选的书（没筛选就用正在写的书）里勾选章节，可一次多章；已在看板上的章节不能重复添加。
- **与定稿锁联动**：章节卡进入「完成」（勾选、拖动、菜单、详情窗改列都算）时把这一章设为定稿，离开「完成」时改回草稿，并提示一句。
  只在看板上操作时联动；手改看板文件、在编辑台改定稿状态不会反过来挪卡片。
- 找不到文件的章节卡（被删了）显示「找不到这一章」，点击不打开，可以在详情里换章节或删除卡片。

### 不做什么

- 还没创建的章节（规划中的章节）——以后再做。
- 编辑台里设定稿 / 改回草稿时自动挪看板卡片。
- 章节卡上显示章纲摘要、批注数。

### 怎么算完

- [x] `npm run verify` 全部通过；检查覆盖：整行链接解析为章节卡、写回往返、批量添加章节、文字卡不受影响；看板移动与定稿联动的接线（源码级）
- [ ] 测试库：添加几章 → 卡片显示字数 / 修改时间；点卡片打开那章；拖到「完成」后编辑台显示定稿锁，拖出后解锁
- [ ] 书桌「计划」卡点章节行打开那章；章节改名后卡片仍能打开
